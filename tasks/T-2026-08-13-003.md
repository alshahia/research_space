## User's literal intent

Build reusable **templates for agents to build apps** - best result, fewest tokens. The agent receives an app idea through an input field, reads the guide/instructions, loads a template, interrogates the user until the requirement is unambiguous, researches the net when needed, and ships a working app. Research first: what exists open-source, how it compares to competitors, what to use and avoid per kind of app, and how to reach a minimal-but-complete working app on the shortest token path.

## Restated goal

Produce a **research report** that answers six questions:

1. **Prior art** - which open-source systems already do prompt-to-app scaffolding, and which are forkable (license, maintenance, star count, architecture).
2. **Competitors** - how the commercial prompt-to-app tools handle intake -> clarify -> scaffold -> iterate, and what is worth copying vs avoiding.
3. **App-kind decision matrix** - what stack/template to use and why, per kind of app.
4. **Token economy** - what actually burns tokens in agent-driven scaffolding and what the shortest path to a working minimal app looks like (checked-in skeleton vs LLM-generated, deterministic scaffolders, progressive disclosure, prompt caching, diff-not-file).
5. **Intake protocol** - how the agent elicits and validates requirements from a one-line idea (adaptive survey, spec-driven development, ambiguity detection, confidence thresholds, when to stop asking).
6. **Audit of `resources/general-app-template`** - what it has, what is missing, what is risky; gap matrix vs the target design.

The deliverable is a research dossier that a later planning phase can decompose into a build plan for the actual template system.
