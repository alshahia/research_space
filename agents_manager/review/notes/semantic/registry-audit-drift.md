# Registry audit footers drift from their own tables (merged-dossier verification)

When verifying a merged source registry (e.g., 99_SOURCES.md built from N angle tables), **never trust the audit footer arithmetic - recount from the table rows**. On T-2026-08-14-003 the footer claimed "Verified count: 105; secondary: 17" while its own parenthetical list contained 29 IDs and the table held 93 verified / 29 secondary / 2 UNVERIFIED. The sum still hit 124 (105+17+2 = 93+29+2), so headline numbers survived; only the per-category audit counts were wrong. LESSON: merge agents copy parenthetical ID lists correctly but often miscount them; a 3-line Python recount (`re.findall(r'^\|\s*(S\d+)\s*\|.*?\|\s*\[(\w+)\]\s*\|', text, re.M)` + Counter) is the check, and the verdict line should cite the recount, not the footer.

Second drift pattern from the same pass: **license strings are the highest-drift field in merged registries.** ReGoap was labeled MIT in the registry row AND in chapter 04 while the primary-verified angle file (raw LICENSE fetch) and the canonical summary both said Apache-2.0 - an unmarked contradiction inside the dossier itself. LESSON: when a registry exists for license hygiene, spot-check every license value against the angle file that originally verified it; flag mismatches as MEDIUM even when both licenses are permissive (the registry's purpose is defeated silently otherwise).
