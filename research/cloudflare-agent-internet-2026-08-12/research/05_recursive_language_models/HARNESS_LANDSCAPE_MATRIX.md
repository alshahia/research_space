## 1. Headline thesis in 30 seconds

The "harness layer" stopped being a side-feature and became a recognized market category in 2026. **Five families** now compete across the open-source segment:

1. **Vendor CLI harnesses** (Claude Code, Codex CLI, Prime Agent, Sourcegraph Amp) — built and shipped by the model labs themselves; the harness is treated as part of the model-product stack.
2. **General-purpose coding harnesses** (Aider, Cline, Kiro, Auggie, OpenCode, Goose, Qwen Code) — designed to be model-agnostic; the harness is the product.
3. **Multi-agent frameworks** (AutoGen, CrewAI, LangGraph, MetaGPT, CAMEL, OpenHands) — emphasis on orchestration, not on coding tasks.
4. **Memory/stateful harnesses** (Letta, MemGPT, Zep) — long-running, persistent agents rather than task-completion loops.
5. **Self-improvement / meta-prompting** (DSPy, TextGrad, STOP, Reflexion, Voyager) — software stacks that *optimize* the harness around an outer model.

Closed-source / VC-funded players (Cursor, Devin, Factory, Replit, Sourcegraph Amp (proprietary mode), GitHub Copilot Agent) are scored separately in §3 — they share the same plumbing but charge for the skill layer.

Prime Agent's edge is the **Recursive Language Model (RLM)** abstraction: long inputs become a Python variable in a persistent REPL, the model writes code to inspect it, and recursive sub-agent calls return *summaries* not raw tokens. The Prime-Agent launch post claims this beats Claude Code and Codex on 6 of 9 long-context evals and matches Opus 5's 95.5% on ARC-AGI 3 (vs. a 30.2% Claude-Opus-5 baseline + a 99.86% reported by an independent engineer named Ryan Brown). All of these number are `[self-reported]` until third-party reproductions appear.

## 5. Sourcing, methodology, and limitations

- **Stars/forks/license**: GitHub HTML pages fetched via `webfetch` on 2026-08-13. API was rate-limited from this host; the HTML `repos` data is identical to the API.
- **Last commit / commit count**: from the same GitHub HTML pages. The "last commit" date is the HEAD commit; if the repo is auto-archiving, the date may be stale.
- **First release**: from the README or the *oldest* reachable release; for projects with no tagged releases (e.g., DB-GPT), I report the README's "since" date rounded to month.
- **Model support**: from the README's "Supported models" section or import-config docs. Claude Code / Codex are explicitly provider-locked; everything else is BYOK.
- **Loop pattern**: from the README's "how it works" + first 100 lines of source where the pattern was ambiguous.
- **Self-improvement**: present iff the harness **edits its own scaffolding at runtime**. Prime Agent has `/refine`. Letta has memory-block rewriting. AutoRAG updates its memory.json. Voyager writes skill files. The rest are *static* even if they support prompt optimization at design time.
- **MCP**: present iff the repo's README or docs page explicitly lists MCP support, OR if the codebase imports the official MCP SDK in its top-level files. (Compile-testable, not PR-only.)
- **Sandbox**: present iff the harness ships with OS-level isolation (Docker, Firecracker, Landlock, or sandbox-exec). Prime Agent's README explicitly says "not a security sandbox" — this is reflected.
