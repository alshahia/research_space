## 1. Executive summary (10-second answer)

- **NotebookLM** (now **Gemini Notebook**) is Google's **source-grounded RAG research assistant**: you upload documents ("sources"), chat with an AI that answers *only from those sources* with inline citations, and generate derived artifacts (notes, study guides, flashcards, mind maps, and the signature **Audio Overviews** — AI podcast discussions).
- **Inputs:** Google Docs/Slides/Sheets, PDF, Word (docx), PPTX, TXT, Markdown, CSV, ePub, images, audio files (30+ codecs), web URLs, YouTube URLs (transcript only), pasted text, Drive files, Gemini chats. Per-source cap: 500k words or 200MB. Up to 600 sources/notebook on the top plan.
- **Outputs:** grounded chat with citations, notes, reports, FAQs, study guides, flashcards, quizzes, infographics, slide decks, data tables, mind maps, **audio overviews (80+ languages)**, video overviews, Deep Research reports; export to Docs/Sheets, download WAV/MP4/PDF/PPTX/CSV/JSON; sharing via link.
- **Competitors:** no full-stack equivalent exists. Closest per axis: ElevenLabs GenFM (audio), Elicit/Consensus (academic citations), ChatGPT/Claude (general grounding), ChatPDF/Adobe (page-level citations), Notion AI (workspace grounding).
- **Open source:** nothing matches NotebookLM end-to-end. Best overall: **Open Notebook** (~36.5k★, MIT — full clone with 1–4 speaker podcasts, REST API). Best audio engine: **Podcastfy**. Best RAG: **RAGFlow** (~87k★, no audio) / **Kotaemon** (best citation UX). ~563 repos tagged `notebooklm` on GitHub.
- **To build one:** it's a standard two-pipeline grounded RAG system (offline index / online query) + a podcast pipeline (script → disfluency pass → TTS). Cost for an MVP ≈ **$35–50/month** hosted (Gemini Flash + pgvector). Fastest path: **fork Open Notebook** or build on the reference architecture; the audio magic is the *script*, not the TTS.

## 2. How NotebookLM operates (architecture)

- **Source-grounded AI:** the model has access ONLY to uploaded sources; it refuses out-of-scope questions ("Gemini Notebook can't answer this question"). No web browsing at chat time, no training on user data (official).
- **Grounded RAG pipeline** (third-party analysis): upload → parse → chunk (usually paragraphs) → embed → vector index → embed query → retrieve top-k → prompt (question + chunks) → Gemini generates → citations inserted. Since Oct 2025 the full **1M-token Gemini context window** is used in chat, which lets it de-emphasize aggressive chunking.
- **Model lineage:** Gemini Pro (Dec 2023) → 1.5 Pro (Jun 2024) → 2.0 Flash (Dec 2024) → 2.5 Flash (May 2025) → Gemini 3 (Dec 2025) → Gemini 3.5 + Antigravity (Jun 2026). Long-generation paths (audio) use bigger models than routine chat.
- **UI (Dec 2024 redesign):** three panels — Sources | Chat (with citations) | Studio (artifact generation).
- **Audio Overviews (the viral feature):** two-stage pipeline — (1) dialogue script generated by Gemini with an explicit **disfluency pass** ("uh", pauses, back-and-forth) — this is "the magic", not the TTS; (2) speech synthesis built on DeepMind's **AudioLM + SoundStorm** research stack. Interactive "Join" mode lets users talk to the hosts.
- **June 2026:** every notebook got a **secure cloud computer** — native code execution for grounded data analysis (Ultra/Pro-first).

## 3. Input support (official table)

| Source type | Notes |
|---|---|
| Google Docs / Slides (≤100 slides) / Sheets (≤100k tokens) | Footnotes/comments stripped |
| PDF, docx, PPTX, TXT, MD, CSV, **ePub** | |
| Images (avif…webp) | Some types work less well |
| Audio (MP3, WAV + ~30 codecs) | Transcribed at import; no Drive import |
| Web URLs | Text only; no paywalls, no images/embedded video |
| YouTube URLs | Transcript only; needs captions; >72h old; 500k-word caption cap |
| Pasted text / Google Drive / Gemini chat import | |
| Deep Research (agentic discovery, Nov 2025) | Web research that auto-imports sources |

Per-source cap: **500,000 words or 200MB** on all plans. Sources/notebook: 50 (free) → 600 (Ultra 30TB).

## 4. Output support

- **Chat:** grounded answers + inline citations (hover = quote, click = jump to passage); saved history; 1M-token context.
- **Studio artifacts:** Audio Overviews (Deep Dive/Brief/Critique/Debate, 80+ languages, interactive Join mode), Video Overviews (+Cinematic on Ultra), Mind Maps, Reports (FAQ/Study Guide/Briefing Doc/Blog), Flashcards, Quizzes, Infographics, Slide Decks, Data Tables, Deep Research reports.
- **Agentic outputs** (Ultra/Pro): charts (png/svg), documents (PDF/DOCX/MD/TXT), images, CSV/JSON, xlsx, pptx.
- **Export/share:** Google Docs/Sheets export, downloads (WAV, MP4, PNG, PPTX…), notebook sharing (viewer/editor + public links), Audio Overview share links. **No full-notebook package export.**
- **API:** enterprise-only (Gemini Notebook Enterprise API on Google Cloud Discovery Engine); no public consumer API (unofficial reverse-engineered SDKs exist: notebooklm-py 18.6k★, notebooklm-sdk).

**Key takeaways:** (1) no full-stack competitor exists — NotebookLM uniquely combines free grounded chat + audio/video overviews + study tools + mixed ingestion; (2) citations are the battleground — page/sentence-level traceability is NotebookLM's known weakness (source-level only); (3) the $20/mo cluster dominates; (4) all prices are point-in-time (pricing churn is real).

## 6. Open-source alternatives — full landscape

~563 repos tagged `notebooklm`; four tiers (all details + consolidated table in [03_opensource/FINDINGS.md](03_opensource/FINDINGS.md)):

**Tier 1 — Full clones:**
- **Open Notebook** (`lfnovo/open-notebook`, ~36.5k★, MIT) — **closest full clone**: FastAPI + Next.js/React + SurrealDB + LangChain; notebooks, PDF/DOCX/web/audio/video/YouTube sources, grounded chat, REST API, 18+ providers, **podcasts with 1–4 speakers + custom profiles** (podcastfy-grade TTS). Weakness: citations admitted "basic".
- **SurfSense** (~15.9k★) — web-connector research platform (Reddit/YT/IG/Amazon…), podcasts, MCP server; custom license.
- **PageLM** (~1.7k★), **KnowNote** (~1.1k★, desktop), **Local-NotebookLM** (~1k★, audio-only), **notex** (Go), + long tail (~20 more small clones).

**Tier 2 — Audio generators:** **Podcastfy** (~6.5k★, Apache-2.0 — **best OSS audio**, ElevenLabs/OpenAI TTS, the engine Open Notebook uses), gabrielchua/open-notebooklm (~2.6k★, MeloTTS, demo down), Meta **NotebookLlama** (open-weights but robotic TTS), run-llama/notebookllama, neuralnoise, NotebookMLX.
**Universal truth: local TTS (Bark/MeloTTS/Kokoro) is the quality ceiling — near-NotebookLM voices require cloud TTS.**

**Tier 3 — RAG platforms (no audio):** RAGFlow (~87k★, deepest document understanding + traceable citations), AnythingLLM (~64.5k★, easiest), Kotaemon (~25.7k★, best citation UX with PDF preview), Onyx (~31.5k★), Khoj (~36.4k★), PrivateGPT (~57.4k★), Open WebUI (~148k★), Dify (~152k★), QAnything, DocsGPT.

**Tier 4 — Frameworks (build-your-own):** LlamaIndex, LangChain, Haystack, LightRAG (graph RAG), Microsoft GraphRAG, AutoRAG, R2R, txtai, LiteLLM (provider gateway).

**Avoid:** Verba (archived), NoobBook (abandoned), open-notebooklm HF demo (down), InsightsLM (n8n backend not OSS), MindsDB/SuperDuperDB (dormant/pivoted).

## 7. If you were asked to build one — how (full spec in [04_build_guide/FINDINGS.md](04_build_guide/FINDINGS.md))

### 7.1 Architecture
Two pipelines sharing a tenant-scoped index:
```
OFFLINE:  parse (PyMuPDF/Docling) → structure-aware chunk (256-512 tok, 10-20% overlap,
          metadata: doc_id/page/heading path) → embed → pgvector + BM25 index
ONLINE:   query → hybrid retrieve (BM25 ∥ dense) → RRF fuse → cross-encoder rerank
          (top-50→top-5) → prompt with numbered chunks → LLM stream → citation validator →
          answer + inline citations (reject uncited claims, confidence-gated abstention)
AUDIO:    retrieve top chunks → outline → dialogue script {speaker,text} → disfluency pass
          → per-speaker TTS → stitch (pydub) → MP3
```

### 7.2 Tech stack (hosted MVP — fastest)
FastAPI + Next.js/React · Postgres+pgvector (+ FTS) · OpenAI/Gemini Flash LLM · text-embedding-3-small · RRF + bge-reranker · PyMuPDF/Docling parsing · faster-whisper/WhisperX transcription · youtube-transcript-api · edge-tts→OpenAI tts-1→ElevenLabs TTS ladder · Celery/Redis async · RAGAS eval · Langfuse observability.

### 7.3 Reuse vs build
- **Ship a product fast → fork `lfnovo/open-notebook`** (MIT, closest parity, podcast pipeline included). Differentiate on citations (its known weakness).
- **Learn/control → build from scratch** on the reference RAG architecture; copy the podcast spec from open-notebook's docs.
- **Don't** start from RAGFlow/Dify as your app (engines, not NotebookLM-shaped products).

### 7.4 Cost
Generation = 80–95% of spend. MVP: 10k queries/mo + 100k docs ≈ **$35–50/mo** (Gemini 2.5 Flash + Qdrant Cloud + near-zero embeddings). Audio: ~$0.15 (OpenAI tts-1) to $3 (ElevenLabs) per 10-min podcast; script gen ~$0.01/episode.

### 7.5 What to AVOID (top pitfalls)
1. **LLM-layer tenant isolation** — enforce at the vector-store query layer (namespace + signed JWT), never via prompt.
2. **Document poisoning / indirect prompt injection** — #1 RAG attack (5 crafted docs manipulate >90% of responses); scan ingestion.
3. **Uncited/phantom answers** — citation validator + confidence-gated abstention at the system level.
4. **Blind fixed-size chunking** of tables/headings; no metadata → no citations, no filtering.
5. **Full reindexes** — chunk-hash delta re-embedding is ~100× cheaper.
6. **Long-context vs RAG** — route, don't go all-in either way (long-context: ~58% needle recall at 1M tokens).
7. **edge-tts in commercial products** — unofficial API, Microsoft ToS risk; fine for prototypes.
8. **Naive per-line TTS without clip caching** — cost/rate-limit blowups; md5-cache clips.
9. **Frontier-model-only routing** — cheap models + prompt caching + answer caching cut spend 50–90%.
10. **Attempting SoundStorm-class dialogue synthesis in an MVP** — the disfluent script + per-line TTS gets 80% of the effect at 1% of the effort.

### 7.6 MVP roadmap (4–6 weeks, single dev)
Phase 0 foundation → Phase 1 ingestion (w1–2) → Phase 2 grounded chat + citations + eval-in-CI (w2–3) → Phase 3 notes/artifacts (w3–4) → Phase 4 Audio Overview (w4–5) → Phase 5 harden (tenancy, poisoning scan, caching, observability) (w5–6). **Audio last, script quality first.**

## 9. OSS-first pass (re-research 2026-08-10) — "prefer free open source"

Re-research with a free/OSS-first lens (2 sub-agents + orchestrator cross-validation). New material is appended to `04_build_guide/FINDINGS.md` §11, `03_opensource/FINDINGS.md` §10, `02_competitors/FINDINGS.md` §6.

### 9.1 The strongest $0 software stack
Fork **Open Notebook** (MIT, ~36.6k★) → **Ollama Qwen3-14B** (or Qwen2.5-7B on 16GB CPU-only) → **BGE-M3** embeddings (MIT, 100+ langs, dense+sparse+ColBERT) → **LanceDB** (Apache-2.0, native BM25 hybrid + RRF) → **bge-reranker-v2-m3** (MIT) → **Kokoro-82M** TTS (Apache-2.0, CPU, TTS Arena #1) → **faster-whisper/whisper.cpp** STT → **Docling** parsing (MIT) → **RAGAS** eval. Zero dollars of software; see §9.4 for the honesty caveats.

### 9.2 Zero-$ scenarios (can it run for free?)
- **(a) 16GB no-GPU laptop** — workable but slow (2–8 tok/s CPU); weakest link = LLM latency + citation reliability.
- **(b) Mac M-series** — the best all-local box (Qwen3-14B + Metal + whisper.cpp ~10× realtime); weakest link = 14B grounding ceiling on long multi-doc questions.
- **(c) Free API tiers only** — demo-grade: Gemini free (1,500 RPD Flash) + Groq free (30 RPM/6K TPM) + ElevenLabs free (10k chars/mo ≈ one 10-min episode); weakest link = TTS monthly cap + chat rate limits.

### 9.3 License traps in the "free" path (must-avoid)
XTTS-v2 (CPML, no license obtainable — Coqui dead) · F5-TTS weights (CC-BY-NC) · jina-embeddings-v3 + NV-Embed (CC-BY-NC) · Command R 35B (CC-BY-NC, only local model with native citations) · edge-tts (ToS risk) · Kokoro's espeak-ng GPL dependency · **GitHub Models retired 2026-07-30** (cross-validated: github.blog changelog) — stale tutorials cite it; replacement = Microsoft Foundry. Free hosting (Render/Cloudflare) is demo-grade only — practical floor is a $4–5/mo VPS.

### 9.4 Honest ceiling of the free path
Local 7–14B models hallucinate citations 17–33% without a validator (mandatory: numbered `[S1..Sn]` chunks + post-hoc validation + constrained decoding), and Kokoro reaches "very good podcast" but not ElevenLabs/NotebookLM-class voices. If the product promises Gemini-class grounding or those voices, budget for the paid tier (original §7.4 estimate: $35–50/mo hosted).

### 9.5 New OSS finds (2026 refresh)
**PaperQA2** (FutureHouse, 9,010★ Apache-2.0, active) — best-in-class citation-grounded RAG, steal its citation discipline · **Cortex** (PndaMan, Apache-2.0, Svelte) — 2026 clone shipping two-host audio overviews + spaced repetition · **OpenBookLM** (MIT, active) — education clone · **mulmocast-cli** (TS, active) — multimodal podcast/video · **Gloss** (AGPL, Rust/Tauri) — best evidence-retrieval-receipt design, currently broken (watch). Corrected: MindsDB → mindshub 39,526★ · SuperDuperDB → superduper 5,308★ (Apache-2.0) · Dify = modified Apache-2.0 (not AGPL). Verdict unchanged: **no OSS project fully matches NotebookLM** — Open Notebook remains the closest; audio gap closing (RAGFlow added TTS output in 2026, Cortex ships two-host audio).

### 9.7 Voicebox & VoiceStudio (user follow-up, 2026-08-10)
- **Meta Voicebox** — NOT usable: weights/code never released (research paper + demo only, since June 2023). Do not design around it; its flow-matching lineage lives on in open models (Dia, OpenAudio S1, Qwen3-TTS).
- **VoiceStudio** (debpalash, formerly OmniVoice-Studio) — the notable find: 100% local OSS "ElevenLabs alternative" (3s zero-shot cloning, voice design, dubbing, audiobook, 14 TTS/11 ASR engines, MCP server). **AGPL-3.0** (commercial license available) — best free voice suite for a voice-first product, but for the podcast pipeline the license-clean path stays Kokoro-82M (Apache-2.0) in an MIT base. Also on GitHub: wtsteward11/VoiceStudio (Chatterbox engine — 23 langs, emotion), latentforge/VoiceStudio (research), plus commercial "Voice Studio" (aiaudiogen). Details: `04_build_guide/FINDINGS.md` §11.5.
