## 1. Plan summary

**Goal.** Produce a build-ready, agent-assignable implementation plan for a LOCAL single-player MOBA in Unity 6.3 LTS: the user controls 1 hero with 4 AI allies versus 5 AI enemies (MVP = 1 hero, 1 lane loop, 2-3 enemy heroes), no multiplayer, no network, no netcode. Every phase carries an owner, an entrance/exit gate, acceptance criteria, effort, and dependencies so master can dispatch am-coder/am-design/am-assets/am-review without re-reading the dossier.

**Scope.** The dossier verdict is FEASIBLE, HIGH confidence, build from scratch (no OSS cornerstone exists; borrow the MIT component layer only). This plan translates the dossier P0-P13 build guide into a 14-phase build, folding the 12 locked user decisions in as first-class data-driven presets rather than hardcoded constants.

**Locked decisions recap (all 12 binding inputs).** Q1 dual-platform day one (desktop + Android, mobile budget is a P0 constraint, not a late pass); Q2 Unity 6.3 LTS; Q3 match duration as user-selectable presets; Q4 lane layout as user-selectable presets; Q5 MVP-scoped v1 with data-driven scale to 5v5; Q6 hybrid difficulty (honest base + merciless cheat tier, one governor); Q7 free stack only; Q8 bespoke GAS-shaped SO ability system (Option C); Q9 free hand-rolled AI tree; Q10 one save system with two entry points (progression + mid-match checkpoint); Q11 vision rulesets user-selectable; Q12 mostly standard projectiles.

**Effort estimate.** Nominal 47-69 phase days (dossier 07 totals). With the 25-30% integration/validation buffer recommended by the research merge pass, 60-90 person-days, i.e. 6-9 weeks full-time or roughly 3-4.5 months solo part-time. Mobile (Q1) and data-driven presets (Q3/Q4/Q11) add integration weight inside the buffer, not new phases.

## 2. Architecture overview

**Project layout (all under `Assets/`, Unity 6.3 LTS URP project).** C# only, no codegen, no Odin, no paid packages (Q7). ASCII-only docs (repo rule, no em/en dashes). Every borrowed asset carries an MIT license header.

```
Assets/
  Scenes/            Bootstrap, DevScene (P1), LaneScene (P2+), DuelScene (P7), MenuScene (P10)
  Scripts/
    Core/            EventBus, ObjectPool, DamageResolver, TimeService (all systems decouple via bus)
    Input/           RtsInput-like action maps (keyboard/mouse + Touch, dual-bound from day one, Q1)
    Movement/        IMovementProvider + CharacterController impl + SteeringOnPath (SetDestination discipline)
    Combat/          Health, Projectile, ability runtime
    Minions/         WaveScheduler, MinionBrain (LoL aggro, S36)
    Towers/          TowerBehaviour (LoL turret model, S38)
    Economy/         GoldXpManager, ItemShop, ItemData
    Vision/          VisibilityGrid + ruleset provider (Q11 presets), brush reveal
    AI/              AiBrain (3-layer tree, Q9), AiPerception, DifficultyGovernor (Q6), AlliedOverrides
    Abilities/       Ability, Effect, Attribute (GAS-shaped, Q8), projectile archetypes (Q12)
    Save/            SaveData DTOs (versioned), SaveManager, CampaignProfile (Q10)
    Settings/        GameSettings, QualityTiers (Q1 dual-platform URP assets)
    UI/              HudController, MenuFlow, PresetPickers (uGUI + TMP)
  Data/              ScriptableObjects: Heroes/, Abilities/, Items/, MatchSettings/, LaneLayouts/, VisionRulesets/, DifficultyPresets/, Tuning/
  Prefabs/           Units/, Projectiles/, Towers/, Brush/, UI/
  Art/  Materials/  Shaders/  Textures/   (placeholders first, free packs at P11)
  Editor/            SaveRoundTripTests, LicenseScan, FrameTimingAudit
```

**Core systems list (dossier 02, all behind the event bus).** champion control (U7), minions (U1), towers/objectives (U2), vision/brush (U4), gold/XP/items (U3/U5), save/load (U14/U22), settings/platform (U6/U18/U15/U16/U17). Ability system (U13) as a GAS-shaped bespoke SO pattern (Q8).

**Data-driven presets (the Q3/Q4/Q11 deliverable).** Three ScriptableObject preset families plus one difficulty family, all user-selectable in the P10 pre-match menu and read by every core system:

| Preset family | Question | Default | Variants | Consumed by |
|---|---|---|---|---|
| `MatchSettings` | Q3 duration | MLBB 10-12 min | MLBB / WildRift 15-20 / LoL 30+ | minion HP, gold ramp, XP curve, tower HP, bot pacing (P2-P3) |
| `LaneLayout` | Q4 layout | symmetric 1-1-1-2 duo | symmetric duo / jungler 1-1-1-1-1 / MLBB asymmetric Gold+EXP | map gen, lane assignment AI, economy (P2, P5) |
| `VisionRuleset` | Q11 vision | MLBB simplified bush | MLBB no-wards / LoL wards+brush / custom | Vision system rules + reveal timers + ward items (P2, P4) |
| `DifficultyPreset` | Q6 difficulty | honest base | Easy/Medium/Hard (honest) + Merciless (cheat overlay) | DifficultyGovernor dials (P7) |

No hardcoded lanes/duration/vision/team-size anywhere. Q5 scaling is the same mechanism: `MatchSettings.TeamSize` and `LaneLayout.LaneCount` drive roster/lane count, so the MVP (1 hero, 1 lane, 2-3 enemies) and the future 5v5 3-lane are the same data shape, just more rows.

**Scaling path MVP to 5v5.** P0-P7 build every system data-driven. The MVP proves the 1-lane loop against 2-3 enemies; a later content pass adds hero rows, lane rows, team-size 5, and lane-assignment rows to the same SOs. No core rewrite. The dossier's P11 content phase is the gated vehicle for this; nothing new is architected at 5v5 time.

**Save semantics (Q10).** One `SaveManager` with two entry points: (a) match-complete progression (hero/level unlocks, campaign profile) and (b) mid-match checkpoint (crash recovery). Versioned DTOs, custom serializers, JsonUtility default (Newtonsoft fallback if a constraint bites), no BinaryFormatter (ADR 4/A6), write-to-temp-then-rename, save queue off-frame.

**House rules baked into every phase.** Local-only (no netcode/lockstep/server sim/matchmaking/anti-cheat/analytics anywhere, ADR 6/A1); free stack only (Q7/A14); Unity 6.3 LTS (Q2/ADR 1); URP (ADR 2/A10); GameObject+MonoBehaviour+SO+event bus (ADR 3/A7); DOTS flagged only as a later escape hatch at horde scale (it does not apply at the ~70-80 entities of a MOBA match); hierarchical hand-authored scripted AI (ADR 5/A2), no RL/ML-Agents/LLM.
