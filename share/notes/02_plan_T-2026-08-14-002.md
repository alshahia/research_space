## 3. Guardrails (9 hard rules, from `05_BUILD_ROADMAP.md` § Guardrails)

Enforced at every review. A violation is a FAIL, not a WARN.

1. NO lockstep/netcode frameworks (local single-player; wrong tool).
2. NO BinaryFormatter (removed in .NET 9; always throws).
3. NO Dictionary in save DTOs (not a serialized field type; the #1 save trap).
4. NO RL/LLM opponent in v1.
5. NO Skinned Mesh Renderers for units (not instanceable).
6. NO baked CPU occlusion culling on open maps (GPU occlusion is the alternative).
7. NO copying code from GPL/unlicensed repos (learn-from only; legal exposure).
8. MIT reuse (MinaPecheux) ONLY with attribution - `ATTRIBUTION.md` at repo root if any code is adapted.
9. Movement abstraction from milestone 2A; building carve hooks from 2B; NEVER retrofit.

Plus: pin every version; re-verify doc URLs at implementation time.

## 4. Architecture contract

### 4.1 Folder layout (created at P2T2)

```
Assets/
  Scenes/            (Bootstrap, DevScene, SaveTest)
  Scripts/
    Core/            (event bus, ObjectPool, GameTime)
    Input/           (InputActionMap wrapper)
    Camera/          (CameraRig, MinimapCamera)
    Selection/       (Selectable, SelectableRegistry, SelectionManager)
    Orders/          (Order, OrderQueue, CommandPipeline)
    Movement/        (IMovementProvider, NavMeshMovementProvider, FormationSlotter)
    Units/           (UnitBrain FSM, UnitStats SO)
    Economy/         (ResourceNode, HarvesterBehaviour, EconomyManager, Stockpile)
    Building/        (PlacementSystem, GhostPreview, ConstructionProgress, ProductionBuilding, ProductionQueue)
    Combat/          (CombatSystem, Health, Projectile)
    FogOfWar/        (VisibilityGrid, FogOfWarRenderer)
    UI/              (HudController, SaveLoadMenu, WorldSpaceHealthBar)
    Save/            (SaveData DTOs, SaveManager, CampaignProfile)
    AI/              (AiPerception, BuildOrderEngine, AiEconomyManager, AiArmyManager,
                      AiCombatManager, AiScoutManager, AiCommander, DifficultyGovernor, AiDebugger)
    Settings/        (GameSettings SO)
  Data/              (SO assets: Units, Buildings, BuildOrders, DifficultyPresets)
  Prefabs/  Art/ (Materials, Atlases, Models, UI)  Shaders/  Editor/
```

### 4.2 Event bus

C# events or ScriptableObject channels (`01` § Architecture verdict). UI and AI consume game events (unit selected, resource changed, building completed, damage dealt, unit died, attack received) through the bus. Direct component references between UI/AI and game systems are review-fail items.

### 4.3 Order schema (created at P2T5; reused by AI in 2E)

```
Order {
  OrderType type;        // Move, AttackMove, Attack, Harvest, Build, Stop, Patrol
  int targetId;          // unit/building registry id, -1 if positional
  Vector3 position;      // world position for positional orders
  int queueSlot;         // append index; Shift places at end
  bool isQueued;         // false = replace current order
}
```
`[Serializable]`, plain fields. `targetId` is a SelectableRegistry id - the registry is the single unit-id authority for orders, save/load, and AI targeting (one id space, no forks). The SAME pipeline executes player and AI orders (`01` § 4; `02` § Coordination notes).

### 4.4 Save DTO schema (created at P2T18; NO Dictionary, version field mandatory)

```
SaveFile        { int version; string mapName; float gameTime; PlayerState player; AiState ai; WorldState world; }
PlayerState     { int resourcesGold; int resourcesWood; List<UnitDto> units; List<BuildingDto> buildings; List<ProductionQueueDto> queues; }
AiState         { same shape as PlayerState }
UnitDto         { int id; string prefabId; Vector3 position; float hp; List<OrderDto> orders; }
BuildingDto     { int id; string prefabId; Vector3 cell; float constructionProgress; }
ProductionQueueDto { string buildingId; List<string> queuedUnitIds; }
WorldState      { int gridWidth; int gridHeight; byte[] explored; byte[] visible; }
CampaignProfile { int version; string playerName; bool[] unlockedMaps; int wins; int losses; string difficultyMode; }
```
FoW grid budget: default map 256x256 tiles -> 64KB per byte array (trivial); any larger grid is a documented decision before 2C/2D land.
Written to `Application.persistentDataPath`; PlayerPrefs for small settings only (`01` § 8; `06` AVOID). Version migration: load reads version, migrates forward or fails with a readable message (2D acceptance).

### 4.5 Visual contract (for am-design + art, from `01` § 10 + `04` § Rendering stack)

- URP Forward; SRP Batcher on; one atlased material per faction (player = blue tint, enemy = red tint) with per-instance tint property; no skinned units.
- Unit budget: low-poly non-skinned prefabs, LOD groups (2 levels), instancing-friendly shared meshes.
- Selection feedback: per-instance shader tint/outline on the shared material (no extra draw calls), marquee rectangle in screen space.
- HUD layout (UI Toolkit): resources top-left; minimap bottom-left; command/selection card bottom-center; build menu bottom-right; top-right map name + time. uGUI world-space: faction-colored health bars above units.
- FoW look: soft-edge render-texture mask; unexplored black, explored gray, visible full color; minimap shows the same mask.
- Accessibility: faction palette should survive red-green color blindness (blue vs orange-red is a safe default).
- Unit readability at 600 units: faction identification works from silhouette + tint at typical zoom; no unit relies on text labels alone.
- World-space bar budget: uGUI bars render for units in viewport + selection only, never all 600 units.

## 5. Milestones (from `05_BUILD_ROADMAP.md` § MVP phases)

### M1 = Phase 2A - Foundation (research P1-P5) | 2-3 wk
Setup (Unity 6.3 LTS + URP template + Input System + AI Navigation, pins recorded), named-action Input Map, CameraRig, selection (registry + spatial hash), order pipeline + Shift queue, IMovementProvider + NavMeshAgent + formations, UnitStats SO + FSM skeleton, DevScene with 40 test units.
**Gate:** squad moves under queued orders; selection semantics complete; no per-frame selection raycasts; camera pan feels snappy (< 100ms perceived lag) and selection feedback is immediate.

### M2 = Phase 2B - Economy, Building, Combat (research P6-P8) | 1.5-2.5 wk
Harvest loop (node -> harvester -> drop-off -> stockpile -> costs), queue-based production, placement (grid snap + validity + ghost + construction + NavMesh carve), combat (attack orders, LOS, damage events), ObjectPool.
**Gate:** harvest -> build -> fight loop plays end to end; carve hooks in from day one.

### M3 = Phase 2C - Fog of War + UI (research P9-P10) | 1-2 wk
VisibilityGrid (logic + AI exposure API), render-texture display + shader, UI Toolkit HUD, uGUI world bars + minimap camera.
**Gate:** FoW hides units from player AND AI (fairness test in acceptance).

### M4 = Phase 2D - Save/Load (research P11 + locked decision 4) | 1-1.5 wk
SaveData DTOs + versioning + JsonUtility, in-game save/load menu, CampaignProfile, automated round-trip editor test.
**Gate:** save -> reload -> identical state (automated); campaign progress persists.

### M5 = Phase 2E - AI Opponent (research P13 + locked decisions 6-7) | 3-6 wk
Perception -> build orders -> economy -> production -> combat -> scouting -> attack scheduler -> difficulty governor -> integration shell (9-system checklist, `02` § System-by-system). AI issues orders only through CommandPipeline. Decision logging + Gizmos are budgeted as tasks (P2T26), not a nicety.
**Gate:** AI completes a full match vs player; 3 difficulty modes selectable and effective.

### M6 = Phase 2F - Performance + Polish (research P12) | 1-2 wk
Pooling/material/instancing audit, GRD evaluation (profile before/after, enable or verdict), free art packs, balance pass, final 9-guardrail audit.
**Gate:** 600 units at 60fps in Player build; 9/9 guardrails clean.
