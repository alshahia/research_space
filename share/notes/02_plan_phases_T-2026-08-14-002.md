## Phase 2A - Foundation (research P1-P5)

**Goal:** A running Unity 6.3 LTS project where the player can pan/zoom the camera, box-select a squad, and issue queued move orders through the command pipeline.

**Deliverables:** Pinned project + packages; Input Action Map; CameraRig; SelectableRegistry selection; Order structs + CommandPipeline; IMovementProvider + NavMeshAgent impl + formation slots; UnitStats ScriptableObjects + unit FSM skeleton; DevScene.

**Tasks:** P2T2-P2T8 (see `tasks/T-2026-08-14-002.md`).

**Per-system checklist contract (from `05_BUILD_ROADMAP.md` § Per-system checklists):**
- Movement: IMovementProvider interface + NavMeshAgent implementation from day one; order queue with Shift append; scale upgrade path documented (NavMesh -> grid A* -> flow fields).
- Selection: SelectableRegistry + spatial hash (no per-frame physics raycasts); click, marquee, Shift add/remove, click-empty deselect.
- Input: named actions from `01_RTS_CORE_ARCHITECTURE.md` § 1 (`SelectUnit, BoxSelectDrag, MoveOrder, AttackOrder, QueueModifier, PanCamera, ZoomCamera, RotateCamera, BuildHotkeys`).

**Done when:** In DevScene: (1) WASD + edge pan, wheel zoom, rotate, minimap jump all work; (2) click selects one unit, drag-box selects many, Shift adds/removes, click-empty deselects; (3) right-click MoveOrder moves the squad with formation slots; (4) Shift-queues two move orders execute in sequence; (5) no per-frame selection raycasts remain (SelectionManager uses the registry); (6) every package pin in manifest.json matches the pinned table in the canonical plan.

## Phase 2B - Economy, Building, Combat (research P6-P8)

**Goal:** The three production pillars loop: harvesters gather, buildings produce, units fight.

**Deliverables:** Resource nodes + harvester loop + drop-off + stockpile + costs; production queues; placement system (grid snap, validity, ghost, construction, NavMesh carve hook); combat (attack orders, LOS, damage events); ObjectPool.

**Tasks:** P2T9-P2T13.

**Per-system checklist contract (from `05_BUILD_ROADMAP.md`):**
- Economy: harvester -> node -> drop-off -> stockpile -> cost loop; queue-based production buildings; ScriptableObject data for all units/buildings/costs.
- Building: grid snap; validity checks (occupied/terrain/resource); ghost preview; construction progress; NavMesh carve hook on completion (from day one, never retrofit).
- Combat: attack orders via command pipeline; LOS checks; damage events through event bus; pooled projectiles/effects/units.

**Done when:** In DevScene: (1) a harvester auto-loops gather -> drop-off -> stockpile and the resource counter ticks up; (2) a production building trains a unit from its queue and costs deduct; (3) placement shows ghost, rejects invalid cells, and completed buildings carve the NavMesh (units path around them); (4) two units fight: attack order, LOS respected, damage events fired, death pools the unit; (5) zero allocations per frame in the harvest loop (Profiler check).

## Phase 2C - Fog of War + UI (research P9-P10)

**Goal:** Fog of war hides the map from both player and AI through one shared visibility model, and the HUD presents the game state through the event bus.

**Deliverables:** Tile visibility grid (logic source of truth) + AI exposure API; render-texture FoW display + shader; UI Toolkit HUD (resources, selection panel, build menu, minimap chrome); uGUI world-space health bars + minimap camera.

**Tasks:** P2T14-P2T17.

**Per-system checklist contract (from `05_BUILD_ROADMAP.md`):**
- FoW: tile visibility grid (explored/unexplored/visible) is the logic source of truth; RenderTexture mask for display; AI perception reads the SAME grid (fairness test: AI cannot see FoW-hidden units).
- UI: UI Toolkit HUD/menus/minimap chrome + uGUI world-space health bars; all UI reads the event bus, zero direct unit coupling.

**Done when:** (1) a unit placed behind a hill/edge of vision disappears from the player view (render mask) AND from a debug dump of the AI perception query; (2) explored tiles stay gray after unit leaves, then re-light on return; (3) HUD resource counter updates from the event bus with zero direct references to EconomyManager; (4) health bars above units update and are faction-colored; (5) minimap shows FoW mask + unit dots.

## Phase 2E - AI Opponent (research P13 + locked decisions 6-7)

**Goal:** A complete hand-rolled opponent that plays a full match against the player, with a single difficulty governor exposing 3 selectable modes.

**Deliverables (9-system checklist from `02_OPPONENT_AI.md` § System-by-system):** perception system; data-driven build-order engine; economy manager; production/army manager; tactical/combat manager; scouting manager; attack scheduler; difficulty governor (SC2 handicap / AoE2 honest / DDA); integration shell (coroutine ticks, event hooks, decision logging + Gizmos).

**Tasks:** P2T22-P2T27.

**Per-system contract:**
- Perception FIRST: AI reads the game only through its own view model fed by the shared FoW grid (`02_OPPONENT_AI.md` § The single most important decision).
- AI issues MOVE ORDERS only through the shared CommandPipeline (`02` § Coordination notes).
- Tick rates: strategy 0.5-2s, tactical 0.1-0.3s, reactive per-frame/event; cached yields, zero per-frame allocations (`02` § Layered shape).
- Difficulty: ONE governor, 3 preset groups (SC2-style dials incl. resource multiplier + vision flag at top level; AoE2 honest dials at resourceMult=1.0/vision=off; DDA nudges dials from a player-performance metric) - user-selectable in settings (`02` § Difficulty; locked decision 7).
- MIT reuse: if MinaPecheux code is adapted (BT, placement, SO patterns), ship an `ATTRIBUTION.md` (locked decision 8; `03` § License risk table).

**Done when:** (1) AI perception cannot see a unit hidden in FoW (automated test in SaveTest scene or DevScene debug view); (2) AI completes a full match vs a passive player on Easy (all 9 systems exercised, decision log non-empty); (3) all three difficulty modes are selectable in Settings and measurably change AI dials; (4) AI wins on Hard and loses on Easy across 3 scripted runs (balance sanity, not guarantee); (5) Profiler shows zero per-frame allocations in AI systems.
