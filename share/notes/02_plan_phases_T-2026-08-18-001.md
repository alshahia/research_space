### Banned-example check (path- and label-aware)

`findstr` cannot prove that a banned phrase appears under an `UNSAFE` label -- it is a flat string matcher and returns a hit whether the phrase is inside a `> UNSAFE --` blockquote, inside a table row, or inside a sentence. The Python script below enforces the path-allow-list AND a label-aware adjacent-context check.

**Allowed files for banned phrases:**
- `opencode-sdk-agent-docs/03_decision_guide.md` (unsafe section)
- `opencode-sdk-agent-docs/09_examples.md` (unsafe callouts)
- `opencode-sdk-agent-docs/10_known_issues_and_troubleshooting.md` (workaround mentions for `#43112`)

**Banned phrases (research-derived):**
- `createOpencodeTui` ([S8])
- `apply_patch` ([S19, #43112])

Label marker accepted by the script: `> UNSAFE` (block) or `## UNSAFE` (heading) within +/- 6 lines of the hit. The known-issues file is exempted from the label check because it documents workarounds, not unsafe examples.

```powershell
$py = @'
import os, re, sys
ROOT = 'opencode-sdk-agent-docs'
ALLOW = {
    '03_decision_guide.md',
    '09_examples.md',
    '10_known_issues_and_troubleshooting.md',
}
KNOWN_ISSUES = '10_known_issues_and_troubleshooting.md'
BANNED = ['createOpencodeTui', 'apply_patch']
CTX = 6
bad = []
for r, _, fs in os.walk(ROOT):
    for f in fs:
        if not f.endswith('.md'):
            continue
        p = os.path.join(r, f)
        rel = os.path.relpath(p, ROOT).replace(os.sep, '/')
        with open(p, 'r', encoding='utf-8') as fh:
            lines = fh.readlines()
        for phrase in BANNED:
            for i, ln in enumerate(lines):
                if phrase not in ln:
                    continue
                if rel not in ALLOW:
                    bad.append((rel, phrase, i+1, 'file not in allow-list'))
                    continue
                if rel == KNOWN_ISSUES:
                    continue
                start = max(0, i - CTX)
                end = min(len(lines), i + CTX + 1)
                window = ''.join(lines[start:end])
                if not re.search(r'> ?UNSAFE|## UNSAFE', window):
                    bad.append((rel, phrase, i+1, 'no UNSAFE label within +/-6 lines'))
for rel, phrase, line, reason in bad:
    print(f'BANNED: {rel}:{line} phrase={phrase!r} reason={reason}')
sys.exit(1 if bad else 0)
'@
py -c $py
```

**Expected stdout:** empty. **Exit code:** 0. Any printed `BANNED:` line = FAIL.

**Honest caveat:** the phrase-vs-allow-list check is exact; the within-file label check is a heuristic over a +/- 6 line window. The window is documented so am-review can re-run with a different window and verify. A more rigorous check would parse Markdown AST; that is out of scope (no new dependency).
