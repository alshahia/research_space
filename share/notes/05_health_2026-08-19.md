## Findings (priority order)

### 1. [CRITICAL] `scripts/validate-frontmatter.py:74` - validator crash on ValueError

When `parse_frontmatter()` raises `ValueError` (line 28 / 37 of the script), `validate_one()` returns the raw list `[str(e)]` (1-tuple) instead of an `(errors, mode)` tuple. The caller at line 119 (`errs, mode = validate_one(path)`) crashes with `not enough values to unpack (expected 2, got 1)`.

**Impact:** running the validator on a directory containing a malformed SKILL.md aborts the whole sweep instead of reporting the bad file. Current directory (`agents_manager/`) has 3 such files. Fix is local: change line 74 to `return ([str(e)], "lenient")` (or whatever default mode applies).

**am-coder fix path:** `scripts/validate-frontmatter.py`, function `validate_one`, line 74.

### 2. [HIGH] `agents_manager/SKILL.md:1` - UTF-8 BOM precedes frontmatter

File starts with `EF BB BF 2D 2D 2D` (UTF-8 BOM + `---`). Validator's `parse_frontmatter` rejects with `must start with `---` on line 1` because `\ufeff` is not stripped.

**Fix path:** strip the BOM (re-encode as UTF-8 without BOM, or apply `\ufeff` strip in the validator per #1 above).

### 3. [HIGH] `agents_manager/research/SKILL.md:1` - same UTF-8 BOM

### 5. [MEDIUM] `scripts/validate-frontmatter.py:44` - multi-line YAML value handling absent

The current regex `r"^([A-Za-z_][A-Za-z0-9_-]*)\s*:\s*(.*)$"` only handles single-line `key: value`. YAML-folded (`>`) or literal (`|`) descriptions would capture only the marker (e.g. `>` or `|`) and lose the body. None of the current 12 SKILL.md files use multi-line YAML, so this is latent. If a future specialist uses `description: >\n  folded text...`, the captured `description` would be either `>` (length 1) — which `if not desc` skips — or completely empty.

**Fix path:** extend `parse_frontmatter` to recognise folded/literal blocks, or document that SKILL.md `name`/`description` must stay single-line.

### 6. [MEDIUM] `bin/agents-manager` shellcheck - SKIPPED (binary unavailable)

`npx --yes shellcheck` triggers auto-download of the `shellcheck` npm package, which itself shells out to a `shellcheck` GitHub release download. Today's attempt hit `403 rate limit exceeded` from the GitHub release endpoint. No local `shellcheck.exe` is installed at `C:\Program Files\shellcheck`, `C:\Tools\shellcheck`, or anywhere on PATH.
