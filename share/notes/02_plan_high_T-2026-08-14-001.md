## Plan-mode review angles (v0.17.0+ reflex)

Four angles to pressure-test the plan against, one finding each. These are the questions a re-dispatch would ask. Run as `plan-ceo-review`, `plan-eng-review`, `plan-design-review`, `plan-devex-review` after this plan is committed.

- **plan-ceo-review** — ambition. Is 8 templates the right count, or does the user actually want fewer (focus) or more (breadth)? The economic break-even in `01_RECOMMENDED_DESIGN.md` §Maintenance story is "~10 apps/quarter"; if the user's actual build cadence is below that, the checked-in skeleton is a net loss. Push on whether the user's own first-quarter usage will clear the breakpoint, and if not, propose a smaller 3-template pilot before committing to all 8.
- **plan-eng-review** — execution. The build order is locked, but the *gating* between sub-phases is implication-only. Specifically: does tier2-ai-chat (3.2) need to re-test tier1 (3.1)'s `npm install` before scaffolding its delta, or does copying the tier1 skeleton + adding AI SDK packages suffice? Pressure-test the copy-then-edit pattern against a cold-start clone where `cp -r ../tier1-standard/skeleton .` is not available (the user's eventual build path is `git clone` + co-located templates, not co-mounted).
- **plan-design-review** — visual coherence. The plan inherits the cinematic-landing shape across 7 templates, but tier2-ai-chat and tier2-saas-bundle have heavy UI (streaming chat, billing portal) that the minimalist tier0-minimal and tier1-standard SKILL.md prose will not exercise. Pressure-test whether the per-tier `SKILL.md` and `memory/` content size stays under Anthropic Skills's <5,000-token Level 2 budget (per `01_RECOMMENDED_DESIGN.md` Decision 1) given the SaaS and AI-chat kinds' increased complexity.
- **plan-devex-review** — developer experience. The plan defines a builder (am-coder) and a verifier (am-review), but not a downstream consumer — the agent at the user's terminal who copies the skeleton and ships an app. TTHW (time-to-hello-world) for a fresh `tier1-standard` clone should be measured: `git clone` → `cd` → `npm install` → `npm run dev` → see one page. If the tier1 spine ships Drizzle + Clerk + better-sqlite3 + Vitest all wired, the first dev-server boot may require env vars the user does not have. Pressure-test whether stub secrets ship by default so TTHW stays <5 minutes.
