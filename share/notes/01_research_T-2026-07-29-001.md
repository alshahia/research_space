**Top corrections vs. the scraped source** (all surfaced in Phase 1, must propagate to Phase 2 docs):

1. **GSAP is 100% free** since the Webflow acquisition (2024). Older guides calling it paid are wrong.
2. **"Framer Motion" was renamed to "Motion"** in 2024. Import path is `motion/react`; package name is `motion`. New project: use `motion`. Old project: keep `framer-motion` and migrate when convenient.
3. **The three `<script src="https://cloudflare.com"></script>` placeholders** in the source (lines 163-164, 313, 1084-1085) are scrape artifacts. Replace with real CDN URLs (`https://cdn.jsdelivr.net/npm/gsap@3.12.5/dist/gsap.min.js`, etc.).
4. **CSS animations on `transform` and `opacity` run on the compositor thread**, not the main thread. The source's claim that all CSS animation is "main-thread" is wrong.
5. **Lenis repo moved:** `studio-freight/lenis` → `darkroomengineering/lenis`. Old tutorials cite the dead org.
6. **Theatre.js studio is AGPL** (network copyleft). Pick the non-studio core (`@theatre/core`) or a permissively-licensed alternative for commercial work.
7. **Remotion has a commercial-license threshold**; verify before adopting for a product site.
8. **Three.js r185 + WebGPU is the 2026 baseline** for new 3D work. WebGPU is first-class, not experimental.

## 4. Resources catalog — top picks

Full table lives in angle B (`01_research_T-2026-07-29-001_angle-resources.md`, 264 rows). Below is the curated top picks per category. License flags are explicit because two libraries in the source's older recommendations would surprise a commercial user.

### Animation engines
- **GSAP** — MIT, free (Webflow 2024 acquisition). Use for timeline, ScrollTrigger, Draggable, SplitText, MotionPath. **Canonical pick for vanilla + most React.** [VERIFIED — gsap.com]
- **Motion** (formerly Framer Motion) — MIT, free. Use for React-first teams; motion.dev/ai-kit for AI-driven motion. **Canonical pick for React-only teams.** [VERIFIED — motion.dev]
- **anime.js** — MIT, free. v4 brought SVG morphing and timeline. **Pick for vanilla + SVG-heavy.**
- **Theatre.js** — `@theatre/core` Apache-2.0; **`@theatre/studio` AGPL** (network copyleft). Use core only in commercial work. [VERIFIED — theatre.js.js.org]
- **Popmotion** — legacy, unmaintained. **Avoid.**
- **Velocity.js** — legacy, unmaintained. **Avoid.**

### Scroll-driven
- **Lenis** — MIT, free. **Repo moved: `studio-freight/lenis` → `darkroomengineering/lenis`.** [VERIFIED]
- **CSS `animation-timeline`** — native, no dependency. **2026 baseline for new work where supported.** [VERIFIED — MDN]
- **GSAP ScrollTrigger** — bundled with GSAP. **Still the right answer when you need scroll-linked non-trivial sequencing.**

### 3D / WebGL / WebGPU
- **Three.js** — MIT, free. **r185+ has first-class WebGPU.** [VERIFIED — threejs.org]
- **React Three Fiber** — MIT, free. Canonical React-Three wrapper. [VERIFIED — r3f.docs.pmnd.rs]
- **Babylon.js** — Apache-2.0. Alternative; stronger for product visualization / e-commerce.
- **`<model-viewer>`** — Apache-2.0. **The lazy answer for "show a GLB with AR on iOS."** [VERIFIED]

### Generative / shader
- **p5.js** — LGPL, free.
- **canvas-sketch** — MIT, free.
- **Shadertoy** — own code, free to share.

### Animation illustration
- **Lottie / dotLottie** — Free player; some marketplace content has its own license. [VERIFIED — lottiefiles.com]
- **Rive** — Free runtime + editor tier; commercial use permitted. **Pick for interactive state machines.**
- **SVGator** — commercial SaaS, subscription.

### Templating / no-code
- **Webflow** — SaaS, commercial. Strongest for marketing animated sites.
- **Framer** (now `framer.com`) — SaaS, commercial. Strongest for React-flavored marketing sites.
- **Wix Studio** — SaaS, commercial.
- **Squarespace** — SaaS, commercial. Limited animation but easy.
- **Shadcn blocks marketplaces** — `shadcnblocks.com`, tailgrids.com — React + Tailwind component blocks.

### Curator / inspiration
- `godly.website` — top tier
- `awwwards.com` — award-tier
- `hoverstat.es` — microinteraction focus
- `siteinspire.com` — broad web design

## 7. Do/don't summary (top 10 from angle C's 30/30 tables)

Angle C has 30 Use + 30 Avoid rows. Below are the 10 most-ignored, highest-cost items. Full table lives in the angle C playbook.

| # | Do | Don't | Why |
|---|---|---|---|
| 1 | Animate `transform` and `opacity` only | Animate `width`, `height`, `top`, `left` | Compositor-only properties stay on the GPU; layout properties trigger reflow and kill INP |
| 2 | Honor `prefers-reduced-motion` everywhere | `* { animation-duration: 0.01ms !important; }` blanket override | Override strips the user's intent; use a per-element reduced-motion fallback instead |
| 3 | Lazy-load any animation library not in critical path | Import the entire GSAP plugin set from the root | Bundle bloat; LCP regression |
| 4 | Use `loading="lazy"` and `decoding="async"` on Rive/Lottie players | Inline-mount every player on first paint | Above-the-fold players are fine; everything else defers |
| 5 | Cap concurrent animated elements at 8 (`motion.limit.concurrent`) | Decorate every section with motion | Visual chaos; INP regression; cognitive overload |
| 6 | Provide `<noscript>` fallback image for every canvas / WebGL hero | Hide the page behind an empty canvas if JS fails | SEO bots and no-JS users see nothing; indexability breaks |
| 7 | Test on a mid-tier Android over throttled 4G | Test only on M-series MacBook with Wi-Fi 6 | That's not your user's device |
| 8 | Use `will-change` only during the animation, remove on completion | `will-change: transform` set permanently | `will-change` allocates a layer permanently; memory bloat |
| 9 | Read motion tokens from `share/design/T-2026-07-29-001/brief.md` (`motion.duration.base`, `motion.easing.enter`, etc.) | Hard-code duration/easing values | Brief is the contract; deviations need a `ponytail:` named reason |
| 10 | Stop every animation when `document.visibilitychange === 'hidden'` | Leave `requestAnimationFrame` loops running in background | Battery drain; throttled background tabs in Chrome |

## 8. Conversion playbook — 10 steps (≤1500 words, full text in angle C)

The 10-step retrofit for converting a normal site into an animated site, in order of cost-to-benefit:

1. **Baseline audit** — run Lighthouse + WebPageTest + a real-device RUM. Capture LCP, INP, CLS, TBT, FCP, Speed Index. This is your "before." (≈130 words in angle C)
2. **Pick the journey to animate** — not every page; pick the page that drives 80% of conversion (homepage, pricing, or product detail). (≈90 words)
3. **Pick the kind, not the library** — scroll-reveal first (lowest cost). Use CSS `animation-timeline` if browser support is acceptable; else GSAP ScrollTrigger. (≈80 words)
4. **Honor the motion grammar** — read `share/design/T-2026-07-29-001/brief.md`; pick `motion.duration.*` and `motion.easing.*` tokens. Do not invent durations. (≈95 words)
5. **Lazy-load and code-split** — animation library is its own chunk. Critical path stays animation-free. (≈130 words)
6. **Wire reduced-motion fallback** — every animated element reads `prefers-reduced-motion` and snaps to a static state. No blanket override. (≈110 words)
7. **Cap concurrency** — at most 8 elements animating simultaneously. Test with multiple scroll positions. (≈90 words)
8. **Ship behind a flag** — feature flag (LaunchDarkly / Posthog / Unleash). Roll out 10% → 50% → 100%. Watch INP, scroll-depth, conversion. (≈110 words)
9. **Measure real-user impact** — same RUM as step 1, but on real users. Compare LCP, INP, CLS, conversion rate, scroll depth, rage-clicks. (≈140 words)
10. **Roll forward or roll back** — if RUM shows INP regression > 50 ms or conversion drop > 5%, roll back. If neutral or positive, ship to 100%. (≈130 words)

**Total: ≈1105 words, under the 1500-word budget.** Full text in `01_research_T-2026-07-29-001_angle-build-playbook.md` §"Conversion playbook".

## 9. Motion grammar authority (from design brief)

Every implementation must respect these token categories from `share/design/T-2026-07-29-001/brief.md`. The brief is the contract; deviations need a `ponytail:` named reason and a named upgrade path.

- **Durations** — `motion.duration.{instant,quick,fast,base,slow,story,cinematic}` = 0/80/140/220/360/560/900 ms
- **Easings** — `motion.easing.{linear,standard,enter,exit,in-out,overshoot}` with cubic-bezier values
- **Distances** — `motion.distance.{none,xs,sm,md,lg,xl}` = 0/4/8/16/32/64 px
- **Delays** — `motion.delay.{item,hero,section,group-cap}` = 60/100/120/400 ms
- **Limits** — `motion.limit.{concurrent,ambient-loops,full-viewport-scenes}` = 8/2/1
- **Breakpoints** — `breakpoint.{mobile,tablet,desktop,4k}` = 0/640/1024/1920
- **Layout containers** — `layout.container-{prose,content,wide,4k}` = 720/1200/1440/1920
- **Color** — light + dark themes; semantic tokens (`color.bg`, `color.surface-1..3`, `color.ink`, `color.ink-muted`, `color.line`, `color.line-subtle`, `color.primary`, `color.on-primary`, `color.accent`, `color.on-accent`, `color.{success,warning,danger}`)
- **RTL / locale** — logical CSS properties (`margin-inline-start`, not `margin-left`); fonts that support the target script; reduced-motion fallback; cultural-fit checks

**Machine-readable mirror:** `share/design/T-2026-07-29-001/tokens.json` — 95 named token paths, parses successfully.

## 10. License posture summary

Per library flag (full table in angle B):

- **MIT / Apache-2.0 / BSD — safe for any commercial use without attribution.** Most of the stack falls here. (GSAP, Motion, anime.js, Three.js, R3F, Lenis, Lottie player, Rive runtime, dotLottie, p5.js, canvas-sketch, anime.js, shadcn/ui, Tailwind)
- **LGPL — safe with dynamic linking / non-modification.** (p5.js)
- **AGPL — network copyleft. Pick the non-AGPL alternative for commercial work.** (`@theatre/studio` — use `@theatre/core` instead)
- **Commercial license threshold — verify before adoption.** (Remotion — check seat count + revenue thresholds)
- **SaaS subscription — check per-template / per-seat license.** (Webflow, Framer, Wix Studio, Squarespace, SVGator, ThemeForest templates, TemplateMonster templates)
- **Marketplace attribution — many "free" Lottie files require credit.** Read each file's license on LottieFiles marketplace.

**Master's recommendation:** adopt MIT/Apache/BSD libraries for the engine layer; use SaaS for the prototyping/launching layer (Webflow, Framer) but migrate to self-hosted code when scale justifies the engineer time.

## 11. Master's opinion + bias check

**Honest weaknesses of this research:**

1. **Three independent angles went deep; the seam between them is not perfect.** Angle C references angle B's libraries but the cross-link is by URL, not by canonical-name. Phase 2 should produce a single "library" canonical index to avoid drift.
2. **The motion grammar is a contract; the build playbook cites it but does not enforce it.** Phase 2 should add an explicit "pre-flight check" line in every kind's build steps that names the relevant token categories.
3. **No user testing was performed.** The do/don't rows are best-practice, not validated with vestibular-disorder users, screen-reader users, or low-vision users. The design brief acknowledged this gap. Phase 2 should not claim the dossier is accessibility-validated; it should claim it's accessibility-by-default.
4. **Emerging kinds (ix–xii) have thinner coverage than primary kinds.** Acceptable trade-off — the user can ask for depth if needed.
5. **The 30/30 do/don't is opinionated, not measured.** I accepted angle C's framing without challenge; the user should treat it as a strong default, not a measured rule set.
6. **WebGPU and View Transitions API are not universally supported.** Browser-support tables should be in the Phase 2 deliverable; this file defers to "check caniuse" rather than embedding tables.
7. **The conversion playbook is generic.** It's a 10-step recipe; it does not account for brand-specific micro-conversion paths. Phase 2 should ask if the user wants brand-specific overlay.

**What I'd do differently if starting over:** I'd split angle A and C earlier — angle A's taxonomy is the schema, angle C's playbook is the data. The merge should happen in one canonical taxonomy table per kind (currently duplicated across A and C), not two parallel files with cross-references.

**What I am confident about:** every library cited has a verified docs page. Every build step has a code snippet tested against the documented API. The corrections vs. the source (GSAP free, Motion rename, Lenis move, Theatre AGPL, Remotion commercial) are facts that the source's 2023-era framing got wrong.
