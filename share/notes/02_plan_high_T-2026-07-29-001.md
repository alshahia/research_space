## Goal

Ship a six-deliverable research dossier on animated websites to `research_doc/animated_website_minimax_3/` covering: (1) kinds/genres/types taxonomy, (2) library/tool/platform catalog with per-row license flags, (3) ready templates (online + offline), (4) per-kind build guides for humans AND LLMs, (5) do/don't with reasons, (6) normal→animated conversion playbook. ## Approach

Phase 3 is one large build, partitioned into **three chunks** so `am-coder` writes one chunk at a time and `am-review` checks one chunk at a time. Chunk size is bounded: each chunk produces ≤16 files, ≤~6000 LOC of markdown, and depends on at most one prior chunk. The motion-grammar contract (`share/design/T-2026-07-29-001/brief.md`) is the cross-cutting constraint every build file must respect — every per-kind build guide starts with a "Pre-flight token map" section naming the relevant tokens (per master synthesis weakness #2).

**Chunk A — Kinds + Resources + Templates.** Files: `00_README.md`, `01_kinds/` (3 files), `02_resources/` (12 files). Covers deliverables 1, 2, 3. No chunk dependency.

**Chunk B — Build guides + Cross-cutting support.** Files: `03_build_guides/` (12 kind files + 1 overview), `06_motion_grammar.md`, `07_license_posture.md`, `08_corrections_vs_source.md`. Covers deliverable 4 + motion/grammar/license context. Depends on Chunk A only for canonical library names; otherwise independent.

**Chunk C — Do/Don't + Conversion + Appendix.** Files: `04_do_dont.md`, `05_conversion_playbook.md`, `99_appendix/{references,glossary,changelog}.md`. Covers deliverables 5, 6 + meta. Depends on Chunks A + B (cites canonical library names + build-guide kind ids).

**Why three chunks, not two or five:** Two would push Chunk A past 15 files (over the v0.7.0+ split trigger). Five would over-fragment and force `am-review` to chase cross-chunk citations. Three matches the user's three- deliverable groupings (kinds/resources, build, do/don't+conversion) plus the support docs that have to be co-located with the build guides.

**Build ordering:** A → B → C, sequential. am-review runs after each chunk. C cannot start until A and B are clean because C's appendix citations and do/don't reasons depend on canonical library names + kind IDs established in A and B.
