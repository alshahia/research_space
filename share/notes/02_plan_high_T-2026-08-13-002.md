# High-Level Plan — make research_space a research-first project

**Date:** 2026-08-13
**Sub-agent:** am-planning
**Task id:** T-2026-08-13-002 (this is the **enhancement plan** derived from the prior research sub-task of the same id; research deliverables at `research/00_*.md` remain untouched per the user's non-goal)
**Standing on:** the 6 angle files + canonical research + master synthesis + 3 deliverables in `research/` (read-only input — not modified by this enhancement)

## Goal

When the user asks the agent to research a topic, the agent should produce top-tier research outputs: citation-rich, self-critical, multi-source, optionally Arabic, and recoverable from prior runs. Default tools only (webfetch, grep, glob, read, write, edit, bash, Playwright if present). No Tavily/Exa/Brave API keys. Personal use, EN + AR, open-source. The orchestrator auto-detects research-y tasks and routes them to the enhanced flow; other tasks keep the standard pipeline unchanged.

## Non-goals

- **No new research app** — `platform/` is out of scope entirely (user constraint).
- **No changes to `research/` or `research_doc/`** — historical artifacts, read-only input.
- **No paid-API integrations** — Tavily, Exa, Brave, Perplexity Sonar, etc. are forbidden.
- **No multi-tenant / auth / billing / monetization** — personal-use single-tenant only.
- **No new orchestrator agents** — the existing 10-agent roster (`master` + `am-research` + `am-planning` + `am-coder` + `am-review` + `am-design` + `am-assets` + `am-investigate` + `am-ship` + `am-health`) stays intact.
- **No release / version bump / CHANGELOG entry** — this is a project-internal enhancement, not a controller release.
- **No LLM-as-judge eval** — human-eval with golden tests + rubric only.

## Approach

The conversion is **a controller-and-research-discipline upgrade, not a product build.** The user already owns (a) a 10-agent orchestrator with adaptive mode + chub + audit trail, (b) 11 shipped reference research outputs that prove the format, and (c) Arabic UI strings. What is missing is the **research discipline inside the orchestrator**: a heuristic that auto-detects research-y tasks, an enhanced `am-research` that uses default tools with strict citation/abstention/synthesis discipline, 7 small skill files (markdown + prompt discipline only, no new code) for arXiv / PubMed / PDF / citation-format / synthesis-pattern / compare-sources / Arabic research, a per-project research-memory playbook that indexes the existing 11 outputs (read-only), an optional multi-agent research loop with verifier (re-uses the existing 10-agent roster), and a human-eval harness with 3 hand-crafted golden topics.

Four adaptive tiers ship. Tier 1 is always-on (foundation: rewrites + reflex to all specialists). Tiers 2–4 activate based on a 4-axis score (intent / evidence / scope / reuse) the master computes from the user task. Non-research tasks bypass Tier 1 entirely and use the standard pipeline as today. The user's prior research format (`research/cloudflare-agent-internet-2026-08-12/00_MASTER_SYNTHESIS.md` style: numbered sources, claim-by-claim fact-check, contradiction table) is the gold standard this plan aims to make repeatable.

## Risks acknowledged

- **R1 — "Research-y" detection false-positives** — the heuristic in Tier 1 may mis-classify a task as research when it is a quick edit, causing wasted dispatch. Mitigation: low-tier intent words ("research", "analyze", "compare", "investigate", "find out", "what is", "how does X work") require a second positive signal (evidence or scope axis > 0) before activating Tier 2+. Sum < 1.5 = standard pipeline unchanged.
- **R2 — Verifier stage inflates cost** — a separate verifier pass doubles LLM tokens. Mitigation: verifier is only invoked when Tier 4 activates (multi-faceted, ambiguous, or has known literature); otherwise `am-research`'s built-in self-critique suffices.
- **R3 — Arabic synthesis quality** — `am-research`'s Arabic prompt template may not match the user's prior `kotobee_publishing/06_arabic_market_deepdive.md` quality bar. Mitigation: the research-ar skill + golden test 4 (Arabic topic, deferred to v1.1 per user scope) gives a feedback loop.
- **R4 — Backward compatibility with the existing 10-agent pipeline** — rewriting `agents_manager/SKILL.md` + 8 specialist SKILL.md files may shift behavior for downstream projects that have installed the controller. Mitigation: changes are append-only (new `## Research mode` section at end of each SKILL.md); the standard pipeline path is preserved; no behavior change when the research-detector scores 0.
- **R5 — Golden tests cover only 3 topics** — human-eval with 3 hand-crafted tests is small; regression may slip through. Mitigation: 3 is the user's explicit choice (per user refinement #5); the rubric is open-ended and the user grades; expanding to 5 topics is a deferred item.
- **R6 — Playwright availability is environment-dependent** — the pdf-fetch skill assumes Playwright is installed. Mitigation: fallback path in the skill uses `webfetch` + Jina Reader (`https://r.jina.ai/<url>`) which is tool-free.

- **A3 — "Research-y" heuristic is a simple word-list + axis sum** — the master does a regex scan for ~12 trigger words and scores 4 axes on a 0–1 scale; the routing table is in the Tier 1 section of `agents_manager/SKILL.md`. If a future version wants a learned classifier, that is a deferred item.
- **A4 — Tier activation thresholds (1.5 / 2.5 / 3.5 sum-of-axes)** are defaults the user can tune in `agents_manager/SKILL.md` § Research-detector. The plan ships these defaults; user can adjust after seeing the first few real classifications.
- **A5 — Golden tests live under `agents_manager/eval/golden-tests/<topic>/`** with one `EXPECTED.md` (rubric) + one `RUN.md` (topic input + acceptance criteria) per topic. The eval runner walks the directories.
- **A6 — Research-detector is opt-out per task.** The user can prepend `/standard` to any task to bypass the detector and use the default pipeline (preserves backward compat for downstream projects that have installed the controller).
- **A7 — The 7 research skills are markdown-only.** Each is a `<500-line` SKILL.md under `agents_manager/research/resources/skills/<name>.md` with: when-to-load, prompt template, webfetch recipe, citation format, example output. No new TypeScript / Python / Bash.
- **A8 — Multi-agent research loop reuses the existing 10-agent roster as-is** (no new agent). The "LeadResearcher" role is the master, "Subagents" are am-research dispatches, "CitationAgent/Verifier" is am-review. This is a documented workflow in `agents_manager/research/resources/multi-agent-loop.md`, not a new specialist.
