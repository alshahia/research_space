## What we know for sure

- The OpenCode SDK ships as the npm package `@opencode-ai/sdk` (MIT, ESM-only, current version 1.18.18, ~6.8M weekly downloads, 875 dependents, last publish 23 minutes before access) [S4].
- The default import (`import { createOpencode } from "@opencode-ai/sdk"`) resolves to the v1 surface at `packages/sdk/js/src/index.ts`; a parallel v2 surface is reachable only via the explicit subpath `@opencode-ai/sdk/v2` [S17].
- The SDK is generated by `@hey-api/openapi-ts` from the server's OpenAPI 3.1 spec served at `GET http://<host>:<port>/doc` [S1, S2].
- The SDK requires the `opencode` CLI binary on `PATH` because `createOpencodeServer` spawns `opencode serve` as a child process via `cross-spawn` and parses the URL from stdout (`opencode server listening on <url>`) [S8, S11].
- The server defaults are `127.0.0.1:4096` and a 5000 ms startup timeout; the SDK aborts and rejects if the URL is not observed within that window [S1, S8].
- Windows process cleanup uses `taskkill /pid <pid> /T /F` (force kill of the process tree), not plain `proc.kill()` [S14].
- The v1 client defaults to `responseStyle: "fields"` (returns `{ data, error, response, request }`); `throwOnError: true` opts into throwing and triggers `wrapClientError`, which converts NamedError-shaped POJOs into real `Error` objects with the parsed body attached under `.cause` [S7, S13].
- The v2 client adds (a) `experimental_workspaceID` config that forwards as an `x-opencode-workspace` header; (b) a response interceptor that throws when the server returns `text/html` (signal of "wrong protocol / version mismatch"); (c) a `data` namespace with a `message.user()` helper that constructs typed `UserMessage + Part[]` payloads for client-side assembly [S9, S10, S12].
- The v2 generated type surface introduces many new event types (`EventMessagePartDelta`, `EventMessagePartUpdated/Removed`, the entire `EventSessionNext*` family for shell/step/text/reasoning/tool/compaction/revert streaming, `EventPermissionV2Asked/Replied`, `EventQuestionV2Asked/Replied/Rejected`, workspace/worktree events, and `Tui*2` events). v1 types do not include these [S15, S16].
- `OPENCODE_CONFIG_CONTENT` is the env-var channel used to inject a JSON-serialized config object at SDK server spawn time (the inline `config` option is serialized there) [S8, S11].
- Authentication for the server itself is HTTP Basic via env vars `OPENCODE_SERVER_PASSWORD` (default username `opencode`, override with `OPENCODE_SERVER_USERNAME`); this is a server-side gate, not an SDK-level concept [S2].
- `OPENCODE_SERVER_PASSWORD` and `OPENCODE_SERVER_USERNAME` apply to both `opencode serve` and `opencode web` (not the SDK directly) [S2].
- `opencode serve` CLI flags: `--port` (default 4096), `--hostname` (default 127.0.0.1), `--mdns` (default false), `--mdns-domain` (default `opencode.local`), `--cors` (repeatable) [S2].
- The official docs page https://opencode.ai/docs/sdk/ documents only the v1 surface; the v2 surface exists in source and is reachable via the `/v2` subpath but has no published guide page [S1, S9, S17].
- Context Hub (`chub`) was not used for `OpenCode SDK` in this dispatch because the package is on npm, generated from the server's own OpenAPI spec, and the source-of-truth is the GitHub repo. Direct fetches of the official docs, the npm page, and the source files in `anomalyco/opencode` covered the same surface with stronger provenance. Fallback to official docs and source is recorded.

## Risks and doubts

- **The official SDK docs page documents only the v1 surface, but the package ships a v2 namespace at `@opencode-ai/sdk/v2`. Agents that default to the docs will not see the v2-only event types (`EventMessagePartDelta`, `EventPermissionV2Asked`, `EventQuestionV2*`, workspace events).** If the dossier anchors on v1, agents adopting v2 will need a separate event-name map.
  - **Severity:** medium
  - **Mitigation:** Include a v1 vs v2 surface-delta table; mark every event/method as (v1), (v2), or (both). Recommend defaulting new code to v2 (subpath) once the agent's CLI is recent enough.
- **The SDK requires the `opencode` CLI binary on `PATH` and parses stdout for the listening URL. Cold-start races (default 5000 ms), non-default port collisions, and any future change to the `opencode server listening on <url>` line format will cause `createOpencode` to reject.** The 5000 ms default is short for cold-start on Windows or when many providers load on first run.
  - **Severity:** medium
  - **Mitigation:** Always pass `timeout: 30000` (or higher) for production agents; treat the `Timeout waiting for server to start` error as a port collision or binary-missing class.
- **Recent (last 7 days, as of 2026-08-18) open SDK-relevant issues include: Go gateway "Endpoint is unavailable" for qwen/grok (#43163, Aug 18, open); Ollama slowness (#43117, Aug 17, open); `write/edit/apply_patch` not trimming trailing whitespace from `filePath` (#43112, Aug 17, open); Azure DeepSeek V4 SDK adapter selection (#43106, Aug 17, open); V2 Google Vertex env-var misclassification (#43075, Aug 17, open); IDE/ACP tool-name `_ide` suffix (#43049, Aug 17, open).** A dossier that does not surface these will mislead agents that try to use `apply_patch` with local models.
  - **Severity:** medium
  - **Mitigation:** Include a "Known issues and mitigations" section that calls out #43112 specifically (workaround: trim `filePath` in the agent's own tool dispatcher before calling the model).
- **`createOpencodeTui` is exported from the SDK but it `stdio: "inherit"`s the CLI's TUI to the parent process.** This will hang any agent that calls it and is almost certainly the wrong API for a non-interactive agent.
  - **Severity:** medium
  - **Mitigation:** Mark `createOpencodeTui` as "do not use from non-interactive agents"; recommend `createOpencode` or `createOpencodeClient` instead.
- **Authentication for the server itself (`OPENCODE_SERVER_PASSWORD`) is Basic Auth with the default username `opencode`.** Any agent that spawns the server should set the env var before exposing the port; otherwise the unauthenticated default is open on `127.0.0.1:4096`.
  - **Severity:** low
  - **Mitigation:** Always set `OPENCODE_SERVER_PASSWORD` (and `OPENCODE_SERVER_USERNAME`) before launching the SDK server in any non-loopback context; pass `--cors` explicitly when the SDK client will be in a browser.
- **`@hey-api/openapi-ts` regenerates `sdk.gen.ts` and `types.gen.ts` from the server's OpenAPI spec.** A user reading the dossier with a CLI version newer than 1.18.x may see new methods or renames that the dossier does not mention. The package.json declares `@hey-api/openapi-ts` 0.90.10 as a dev dependency, so regeneration is gated on the package being built locally.
  - **Severity:** low
  - **Mitigation:** Pin the docs to a CLI version (1.18.x); include a "regenerate from your CLI's OpenAPI spec" pointer for users on newer CLIs.
- **The v2 client's HTML-response guard (`throw new Error("Request is not supported by this version of OpenCode Server ...")`) means a v2 SDK pointed at a v1 server will throw on every call.** Mixing versions breaks silently with no version negotiation.
  - **Severity:** medium
  - **Mitigation:** Add a "match SDK version to CLI version" note and a version-detection probe (`GET /global/health`, compare `version` against the package version).

## Technical findings

- **`@opencode-ai/sdk` v1.18.18 is the current default export.** MIT, ESM (`"type": "module"`), build via `bun ./script/build.ts`, test via `bun test`, typecheck via `tsgo --noEmit` [S4, S17].
- **Exports map (v1.18.18 package.json):** `.` -> `src/index.ts`; `./client` -> `src/client.ts`; `./server` -> `src/server.ts`; `./v2` -> `src/v2/index.ts`; `./v2/client` -> `src/v2/client.ts`; `./v2/server` -> `src/v2/server.ts`; `./v2/gen/client` -> generated client; `./v2/types` -> generated types [S17].
- **v1 `createOpencode(options?)` returns `{ client, server }`.** Internally it calls `createOpencodeServer({...options})` then `createOpencodeClient({ baseUrl: server.url })`; one call covers both halves of the lifecycle [S6, S8].
- **`ServerOptions`:** `hostname?` (default `127.0.0.1`), `port?` (default `4096`), `signal?` (AbortSignal for cancellation), `timeout?` (default `5000` ms), `config?` (full `Config` object, JSON-serialized into `OPENCODE_CONFIG_CONTENT`) [S1, S8].
- **`createOpencodeClient(config?)` accepts `baseUrl`, `fetch`, `parseAs`, `responseStyle` (`"data" | "fields"`, default `"fields"`), `throwOnError`, plus the SDK-specific `directory` (URL-encodes into `x-opencode-directory` header) and v2-only `experimental_workspaceID` [S7, S10].
- **The v1 client has a request interceptor that promotes the `x-opencode-directory` header to the `?directory=` query param on `GET`/`HEAD` requests, so it works against both the SDK-style headers and the raw HTTP API [S7].** v2 also adds `/api/` path-prefix detection that promotes both `directory` and `workspace` to `?location[directory]=` form when the request targets an `/api/...` route [S10].
- **`createOpencodeClient` overrides `fetch` with a wrapper that sets `req.timeout = false` on the Request object before calling `fetch(req)` so that a custom `AbortSignal` (passed via `signal` to a method, not the client) does not get clobbered by Node's default fetch timeout [S7].**
- **`createOpencodeTui(options?)` is a separate API that spawns the `opencode` CLI with `stdio: "inherit"` and options `--project`, `--model`, `--session`, `--agent`. It is meant for driving the interactive TUI from a parent terminal, not for non-interactive agents [S8].**
- **`createOpencodeServer` rejects with a `Timeout` Error after `options.timeout` ms if the stdout "opencode server listening" line is not seen, and also rejects if the subprocess exits before the URL is captured [S8].**
- **The full server-side API surface (all confirmed via the docs page and the generated client) [S2, S7]:**
  - **Global**: `GET /global/health` (`{ healthy: true, version: string }`); `GET /global/event` (SSE event stream; v1 supports `onSseError`/`onSseEvent`/`sseDefaultRetryDelay`/`sseMaxRetryAttempts`/`sseMaxRetryDelay` via the `@hey-api` SSE options).
  - **Instance**: `POST /instance/dispose` (returns boolean; disposes the current instance).
  - **Project**: `GET /project` (list); `GET /project/current` (current).
  - **Path**: `GET /path`; `GET /vcs` (VCS info).
  - **Config**: `GET /config`, `PATCH /config`, `GET /config/providers`.
  - **Tools (Experimental)**: `GET /experimental/tool/ids`, `GET /experimental/tool?provider=&model=`.
  - **Ptys**: list/create/remove/get/update/connect.
  - **Auth**: `PUT /auth/:id` (set credentials; body matches provider schema).
  - **Providers**: list, auth, oauth authorize, oauth callback.
  - **Files**: `GET /find?pattern=` (text search, returns `{ path, lines, line_number, absolute_offset, submatches }[]`); `GET /find/file?query=&type=&directory=&limit=&dirs=` (path list, 1-200 limit); `GET /find/symbol?query=`; `GET /file?path=` (list dir); `GET /file/content?path=` (read file); `GET /file/status`.
  - **Sessions**: list, status, create (`POST /session` body `{ parentID?, title? }`), get, delete, update (title), children, todo, init (`POST /session/:id/init` body `{ messageID, providerID, modelID }`), fork (`POST /session/:id/fork` body `{ messageID? }`), abort, unshare, share, diff, summarize, messages, message, prompt, promptAsync, command, shell, revert, unrevert, permissions (`POST /session/:id/permissions/:permissionID`).
  - **Commands**: `GET /command` (list).
  - **MCP**: `GET /mcp`, `POST /mcp` (dynamic add), `POST /mcp/{name}/auth` (start OAuth), OAuth callback/auth status/auth remove.
  - **LSP**: `GET /lsp` (status array).
  - **Formatter**: `GET /formatter` (status array).
  - **TUI**: `POST /tui/append-prompt`, `POST /tui/open-help`, `POST /tui/open-sessions`, `POST /tui/open-themes`, `POST /tui/open-models`, `POST /tui/submit-prompt`, `POST /tui/clear-prompt`, `POST /tui/execute-command` (body `{ command }`), `POST /tui/show-toast` (body `{ title?, message, variant }`), `GET /tui/control/next` (long-poll for next control request), `POST /tui/control/response` (body `{ body }`).
- **`Session.prompt` body shape:** `{ model: { providerID, modelID }, parts: Part[], noReply?: boolean }`. `parts` items include `{ type: "text", text }`, `{ type: "file", path, content? }`, `{ type: "tool", tool }` and others defined in `types.gen.ts` [S1, S15].
- **`Session.prompt` returns either an array of messages or, with the structured-output `format` field, a result whose `info.error.name === "StructuredOutputError"` if the model failed to produce valid JSON after all retries [S1].**
- **`find.text` returns `{ path, lines, line_number, absolute_offset, submatches }[]`.** `find.files` supports `type` (`"file" | "directory"`), `directory` (override project root), `limit` (1-200) [S1, S2].
- **`file.read` returns `{ type: "raw" | "patch", content: string }`.** `file.status` returns `File[]` (status of VCS-tracked files) [S1].
- **`session.command` and `session.shell` exist as separate endpoints.** Both take a session ID; the docs page references both in the example tables but the full body shape is in `types.gen.ts` [S1, S2].
- **Types are auto-generated from `GET /doc` (OpenAPI 3.1 spec) and exported as `Session`, `Message`, `Part`, `Config`, `Provider`, `Symbol`, `File`, `LSPStatus`, `FormatterStatus`, `MCPStatus`, etc. from `@opencode-ai/sdk` [S1].**
- **Error contract (v1 client):** Without `throwOnError`, the SDK returns a result tuple (responseStyle `"fields"`). With `throwOnError: true`, the SDK throws an `Error` whose message is the most informative string available (`.data.message` > `.message` > `.name` > a derived `METHOD URL -> status statusText` description) and attaches `{ body, status }` under `.cause` [S13].
- **The empty-body / network-failure path is handled by `wrapClientError`:** if the response is empty/undefined/null, it returns `new Error("opencode server METHOD URL: (empty response body)")` (or `"network error (no response)"` when no response was received), again with `{ body, status }` on `.cause` [S13].
- **The v2 client adds a `response.use` interceptor that throws `Error("Request is not supported by this version of OpenCode Server (Server responded with text/html)")` on any HTML response, which is the canonical signal of an SDK/server version mismatch [S10].**
- **The v2 `data` namespace exports a `message.user({ sessionID, agent, model, parts })` helper that returns `{ info: UserMessage, parts: Part[] }` with `id`, `time`, `role: "user"` filled in and per-part `id`, `sessionID`, `messageID` populated. This is a client-side convenience for assembling prompt bodies; the server still generates the canonical IDs on receipt [S12].**
- **`x-opencode-directory` is the per-request project-root override.** Setting it (or passing `directory` to `createOpencodeClient`) makes all GET/HEAD calls carry `?directory=<encoded>` so that the server routes them against the right project, without callers having to repeat the query parameter [S7].
- **The `opencode` CLI binary is required at `PATH`.** The SDK does not bundle it; `bin/sh: opencode: command not found` from `cross-spawn` will surface as a generic spawn error wrapped by the server's `proc.on("error", ...)` handler [S8].
- **Release v1.18.9 (Jul 28, 2026) notes a single SDK-adjacent bugfix: "Restored compatibility with legacy MCP SDK clients" [S21].** This implies a recent breakage of older MCP clients and is the only release-tagged SDK bugfix visible in the first page of SDK-related releases; older releases predate it.
- **The npm package was last published 23 minutes before the docs page access, with version 1.18.18. The release list on the SDK query contains 10 entries spanning v1.15.13 to v1.18.9 (Jul 28, 2026).** A 1.18.10-1.18.18 sequence of patches exists between release v1.18.9 and npm 1.18.18 but no per-tag SDK release notes were found in the first page [S21, S4].
- **The repo (`anomalyco/opencode`, 199k stars, 25.6k forks, 15,439 commits on `dev`) ships the SDK as `packages/sdk/js/` [S5].** The CLI binary itself (`packages/opencode/`) depends on `@opencode-ai/sdk`, which is why `process.ts` is "duplicated" between the two packages (cycle avoidance) [S14].
- **The `opencode` CLI's own internal use of the SDK (`packages/opencode/src/util/process.ts`) is the reference for how the maintainers expect subprocess lifecycle to work; copying it verbatim is the safe path [S14].**
- **Issue #42541 (Aug 14, 2026, closed completed) reported that in the v2 server the `question` tool's SSE broadcast was missing (`GET /api/question/request` always empty, no `question.asked` event). It was closed completed before the current access date; this is the strongest evidence that v2 has had real bugs caught and fixed during the 1.18.x patch series [S20].**
- **Issue #43112 (Aug 17, 2026, open) is the highest-priority "known failure mode" for agent dispatchers: the `write`/`edit`/`apply_patch` tools do not trim trailing whitespace from `filePath`, so local models that emit a newline inside the JSON string end up creating files whose names literally contain a newline. The workaround is to trim in the caller before issuing the tool call; the proper fix is on the opencode server side (assignee `neriousy` listed) [S19].**
- **Issue #43163 (Aug 18, 2026, open) reports the opencode-go gateway returning `Upstream request failed: Endpoint is unavailable` for qwen3.7-plus / qwen3.7-max / grok-4.5 only, with kimi-k3 / glm-5.2 / minimax-m3 / gpt-5.6-luna working. The error string is not in the opencode client binary, so it originates from the gateway upstream. This is a server/gateway issue, not SDK, but an agent that relies on these specific models will see it [S18].**
- **The npm page lists `1 Dependency` and `cross-spawn` as the runtime dep [S4, S17].** This means the SDK's only hard runtime dependency is `cross-spawn` (which itself transitively pulls nothing else of consequence on common Node versions).
- **The SDK source files are all written in modern TypeScript with ESM imports; `tsconfig` references `@tsconfig/node22` so the SDK targets Node 22+ [S17].** Agents on older Node runtimes will fail typecheck/build but should still run the published `dist` via `npm install`.

## Example inventory for the later writer

Safe (mark as recommended):
1. **Minimal embedded server + client** (`createOpencode()` then `client.session.create({ body: { title } })` then `client.session.prompt({ path: { id }, body: { model: { providerID, modelID }, parts: [{ type: "text", text }] } })`).
2. **Connect to existing server** (`createOpencodeClient({ baseUrl: "http://localhost:4096", directory: "/path/to/project" })` - the `directory` option rewrites into `x-opencode-directory` and is the cleanest way to point at a specific project).
3. **Create / list / get / delete session** (the four CRUD endpoints; trivial wrappers).
4. **Send a prompt and read the response** (sync `session.prompt` returns the messages; for streaming use SSE via `client.event.subscribe()` or the `@hey-api` SSE options).
5. **Structured output** (`session.prompt` with `body.format: { type: "json_schema", schema: {...} }`; handle `result.data.info.error?.name === "StructuredOutputError"`).
6. **File search and read** (`find.text`, `find.files`, `file.read`).
7. **Config / providers** (`config.get`, `config.providers`).
8. **Error handling with `throwOnError: true`** (so `Error.message` and `Error.cause` are populated).
9. **Cleanup** (call `server.close()` in a `finally`; on Win32 the SDK uses `taskkill /T /F` so the child + descendants are reaped).

Unsafe / misleading (mark as "do not"):
1. **`createOpencodeTui()` from a non-interactive agent** (`stdio: "inherit"` will hang the parent process).
2. **`session.prompt` without explicit `model: { providerID, modelID }`** (silently uses the user's saved default - rarely what an agent wants; pin the model).
3. **Calling `apply_patch` / `write` / `edit` via a model that emits trailing whitespace in tool arguments** without first trimming in the caller (see #43112).
4. **Mixing v1 SDK with v2 server (or vice versa)** without version probing; the v2 HTML-response guard will throw on every call against a v1 server.
5. **Exposing `OPENCODE_SERVER_PASSWORD=...` only in dev** (production agents should always set it; the default unauthenticated server listens on `127.0.0.1:4096` which is safer than `0.0.0.0:4096` but still has no auth).
6. **Spawning the SDK server with `timeout: 5000` in production** (default is too short for cold-start with many providers; pass `timeout: 30000` or higher).
