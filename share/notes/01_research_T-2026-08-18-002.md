2. **Documentation land-grab:** the v8 docs site removed per-framework conversion recipes (Vite/Next/SvelteKit) from its sitemap; angle B reconstructed those from the v6 guides + the `declarations.ts` schema + npm metadata. Source-of-truth discipline demands the dossier cite the v6 doc URLs and flag the gap, not pretend v8 has them.
3. **CLI v8 is broken by upstream tar v7 security patch** (issue #8573). v6 of `@capacitor/cli` works. Dossier must pin `@capacitor/cli@^8.0.0` only AFTER checking for the patch; otherwise `^6`.
4. **Cordova `--platform` flag deprecated** in v7+; project adds must use the `cap add ios` / `cap add android` form.
5. **Native bridge contract** -- plugin count is 39 official plugins as of 2026-08-18 (verified via `npm view` against `@capacitor/*` scope, not the older 23-plugin inventory).

## Merged risk register (HIGH risks only -- full register per angle file)

The planner must surface every HIGH risk to the dossier author. They are not blockers; they are gates that the dossier must address in writing.

### Risks from angle A (core)

- **HIGH-A1 -- v9.0.0-alpha.6 ships a broken Capacitor.framework on iOS** (issue #8560, opened 2026-07). The framework is nested incorrectly, breaks `pod install`. Verify against the dossier's recommended-version block; never recommend `next` to consumers.
- **HIGH-A2 -- `@capacitor/cli@<8` broken by tar v7 patch** (issue #8573, 2026-07). The CLI's archive-walk path breaks under tar v7's stricter archive-header validation. Pin `@capacitor/cli@~8.0.0` unless v6 is required for a Cordova migration.

### Risks from angle B (conversion)

- **HIGH-B1 -- white screen on launch** when `webDir` is mis-set or the bundler emits an absolute path. Fix: `base: './'` in Vite, `output: 'export'` + `dist/` for Next.js, validate `cap copy` produces a non-empty `ios/App/public/` (or symlink) before each `cap sync`.
- **HIGH-B2 -- scheme-swap data loss** on iOS when a user is logged into `localhost:5173` via HMR then opens the bundled `capacitor://` scheme. Solution: gate all auth/cookies on the bundled scheme; never run auth in HMR mode for prod-shaped data.
- **HIGH-B3 -- Android 16 status-bar no-op** without `WindowCompat.setDecorFitsSystemWindows(window, false)` and the right insets dispatcher. Document the OS-version matrix and the `@capacitor/status-bar` Style.Light vs Style.Dark contract.
- **HIGH-B4 -- OAuth callback loss** when redirect URI is bound to `localhost` only; `@capacitor/browser` callback handling. Solution: register both `https://yourapp.com/auth/callback` and a custom `capacitor://your.app.id/auth/callback`; verify in-app.
- **HIGH-B5 -- base-path 404 soup** when bundler emits `/assets/index-abc123.js` but WebView's `webDir` has no fallback to `index.html` for SPA routes. Fix: `server.androidScheme: 'https'` + a Capacitor-side route handler in `AndroidManifest.xml`'s `<intent-filter>` and a `UniversalLinks` config on iOS; or use Ionic's `IonicRouteStrategy` if Ionic is in use.

### Risks from angle C (ecosystem)

- **HIGH-C1 -- Ionic Framework vs Konsta UI misuse** -- choosing Konsta UI when the app needs Cordova-plugin parity (push notifications deep integration, deep links, biometric auth) loses days of work. Decision rule: prefer Ionic unless the app is a lightweight shell with no auth and no PWA fallback; then Konsta + Tailwind.
- **HIGH-C2 -- CodePush is RN-only** -- no Capacitor first-party OTA story. Capgo is the credible OSS third-party for OTA; commercial SaaS exists; update via `@capacitor/push-notifications` for marketing banners + `live reload` for the marketing landing only.

Top user-facing questions (the rest are planning-only / non-user-facing):

1. **Anchor version: Capacitor 8 (current) or 9 (next)?** Default: **v8.5.0**. Dossier must include a forward-compat note: when v9 stabilizes, the conversion recipes in `02-conversion-guide.md` are the same; the CLI command differences are minimal.
2. **Bundler scope: Vite-only or full coverage?** Default: **full coverage** (Vite, Next.js, Vue+Vite, Angular, SvelteKit, plain Webpack/CRA, plain HTML); Vite is the lead, others fall under it.
3. **iOS + Android + Web, or iOS + Android only?** Default: **iOS + Android + Web** (web is the dev loop; the same `webDir` also serves PWA when called for).
4. **PWA coexistence: yes or no?** Default: **yes, optional**. The dossier documents both: (a) native-only (no service worker, `webDir` is the Capacitor bundle), (b) PWA-aware (service worker registered only when the User-Agent is the WebView; the native WebView will not run the SW because the WebView's UA is unique to Android WebView).
5. **Auth model: in-app auth or web-redirect?** Default: **document both**; recommend `@capacitor/browser` + a custom scheme registered in `cap config > server > iosScheme`/`androidScheme` for in-app web flows; recommend in-app native form for OAuth-heavy apps.
6. **Near-native priority list.** Default: **safe-area + status bar + splash + haptics + back-button handling + dark-mode-follow** in that order, with a "good-enough" mark at #4 and a "exceeds PWA feel" mark at #6.
7. **Cordova predecessor yes/no?** Default: **conditional**: document `npx cap migrate cordova` AND the `cordova-plugin-*` compat shim; do not assume any given user is migrating.
