# Conversion playbook — normal site to animated site

Use this as an incremental retrofit for `kind-i` through `kind-xii`. The goal is better hierarchy and feedback without hiding content, breaking navigation, or making performance a guess. Every motion choice maps to `share/design/T-2026-07-29-001/brief.md` (`BRIEF §§4–7`).

| Step | Human action | Agent-verifiable check |
|---:|---|---|
| 1. Audit | Run Lighthouse, axe-core, and WebPageTest on the current site. Record LCP, INP, CLS, TBT, JS size, DOM size, breakpoints, fonts, and the three highest-value user journeys. Treat the scrape as evidence only. | Save a baseline artifact with all metrics; assert the three journeys are named and the current reduced-motion, keyboard, and no-JS states are captured. Tools: Lighthouse CI (Apache-2.0), axe-core (MPL-2.0), WebPageTest service (SaaS/free tiers; review account terms). Cite `CAN §8`; `PLAY Step 1`. |
| 2. Pick the journey and kind | Choose one conversion-critical page, then map each section to a canonical kind. Start with `kind-i` or `kind-viii`; reserve `kind-ii`, `kind-iii`, `kind-ix`, and `kind-xi` for a measured need. Keep one dominant focal point. | Produce a section-to-kind table with trigger, surface, fallback, and success metric. Reject any section with no content or orientation benefit. Cite `CAN §§3,8`; `BRIEF §4`. |
| 3. Write the motion contract | Select the brief intensity profile and name token paths: `motion.duration.*`, `motion.easing.*`, `motion.distance.*`, `motion.delay.*`, and relevant `motion.limit.*`. Use logical `start`/`end`; do not invent timings. | Lint the design note for dot-separated token paths; fail if motion prose contains an unreferenced duration or if RTL and reduced-motion mappings are absent. Cite `BRIEF §§4,8,9`. |
| 4. Choose the smallest stack | Add native CSS first. If choreography needs a JS engine, choose GSAP (MIT, free) or Motion (MIT; package `motion`, import `motion/react`) rather than mixing engines on one surface. Add Lenis (MIT) only when smooth-scroll behavior is justified. | Compare bundle impact before/after; assert one primary engine per page and a documented license posture for every selected library. Cite `PLAY Step 4`; `CAN §4`; official GSAP, Motion, and Lenis docs. |
| 5. Enhance progressively | Layer CSS hover/focus/reveal, then JS timelines, then WebGL. Use CSS `animation-timeline` as the `kind-i` alternate; use Three.js r185+ (MIT) or R3F (MIT) only after a poster and WebGL fallback exist. | After each layer, run Playwright (Apache-2.0) smoke tests and Lighthouse CI (Apache-2.0). Verify the no-JS page remains readable and the WebGL layer is feature-detected. Cite `BRIEF §6`; `PLAY Steps 5–6`. |
| 6. Add fallback and reduced motion | For every animated element, provide a final readable state. Under reduced motion, use `motion.duration.instant`, `motion.distance.none`, static representative frames, or normal document flow; retain immediate status feedback. | Run the OS/browser reduced-motion setting through every journey; assert content is visible, scroll is not locked, focus order is unchanged, and autoplay loops are paused. Cite `BRIEF §5`; `PLAY Step 8`. |
| 7. Enforce budgets | Reserve media dimensions, lazy-load below-the-fold players, pause offscreen work, and keep active tracks at `motion.limit.concurrent`. Track LCP, INP, CLS, TBT, JS, and CSS budgets in Lighthouse CI. | Fail CI if LCP > 2.5s, INP > 200ms, CLS > 0.1, TBT > 200ms, total JS > 200KB gzip, total CSS > 50KB gzip, or any agreed baseline regresses by >10%. Cite `BRIEF §6`; `PLAY Step 7`. |
| 8. Test behavior | Use Playwright (Apache-2.0) for journeys and visual snapshots, axe-core (MPL-2.0) for serious/critical accessibility issues, and Lighthouse CI (Apache-2.0) for performance. Cover Chrome, Edge, Safari, Firefox, mobile Safari, and Chrome Android last-two-version targets. | Assert keyboard operation, `:focus-visible`, touch targets at `size.touch-target`, no flash hazard, modifier-click preservation, View Transitions feature fallback, and no active RAF when hidden. Cite `CAN §2`; `PLAY Step 9`. |
| 9. Roll out with measurement | Put the animation behind a flag. Launch at 10%, compare treatment with control using LCP, INP, CLS, scroll depth, rage clicks, and conversion. Flag platforms need license/terms review: LaunchDarkly (commercial SaaS), PostHog (MIT self-hosted plus cloud SaaS), Unleash (Apache-2.0 core plus hosted SaaS). `web-vitals` is Apache-2.0. | Assert exposure is recorded, control is retained, RUM events have consent/region handling, and dashboards segment mobile, desktop, and 4K-class widths without multiplying motion distances. Cite `BRIEF §8`; `CAN §8`; Web Vitals docs. |
| 10. Roll forward or roll back | Promote only when the measured experience is neutral or better. Roll back when INP regresses by >50ms or conversion falls by >5%; first simplify concurrency, shaders, or smooth scroll, then disable the flag. Keep a CSS motion-scale escape hatch. | Exercise the rollback in production-like conditions; assert readable final states, native scrolling, no orphaned listeners, and a reversible flag. Record the decision and next hypothesis. Cite `CAN §8`; `PLAY Step 10`; `BRIEF §§5–7`. |
