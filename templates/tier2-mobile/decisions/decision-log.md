| 2026-08-14 | am-coder (Phase 3.3) | Listed Expo + Capacitor dep sets as `optionalDependencies` in `package.json`. | Installing the full Expo SDK = ~500MB+ (native deps for iOS + Android). Installing `@capacitor/core` + `@capacitor/cli` + `@capacitor/app` + `@capacitor/ios` + `@capacitor/android` + `@capacitor/haptics` + `@capacitor/keyboard` = ~50MB. Listing as `optionalDependencies` lets `npm install` succeed without the platform SDKs; the postinstall script (or `scripts/switch-target.sh`) refreshes deps for the active target. The actual production deploy will install the active target's deps. |
| 2026-08-14 | am-coder (Phase 3.3) | `deepLinking.ts` uses dynamic imports for the platform-specific SDK. | `expo-linking` and `@capacitor/app` are mutually exclusive at runtime. Top-level imports would force both SDKs into the Vite bundle. Dynamic `await import()` keeps the bundle lean and lets the test stub the imports. |
| 2026-08-14 | am-coder (Phase 3.3) | Smoke test renders `<View />` and `<Text />` as inline DOM wrappers, not `react-native` imports. | The skeleton is bundled with Vite + jsdom for testing. `react-native` and `react-native-web` are not installed (they pull in ~50MB+ of native shims). The inline `<View>` and `<Text>` wrappers in `app/_layout.tsx` render as `div` and `span` for the test; production Expo builds swap these for `react-native` imports via file replacement OR via `react-native-web` aliasing. The SPEC.md documents this as a "spine shape; production swaps the wrappers". |
| 2026-08-14 | am-coder (Phase 3.3) | `expo-doctor.test.ts` and `cap-doctor.test.ts` read the config files, NOT invoke the actual doctor commands. | Per dispatch: "Real-device boot deferred. Do not attempt it. Do not install Xcode/Android Studio." The Windows host has no JDK 21 + Android SDK for `npx cap doctor`; the full Expo SDK isn't installed for `npx expo-doctor`. The tests verify the config files have the right structure (bundleIdentifier, applicationId, appId, webDir) — which is what the doctor commands would check first. The actual full doctor runs are deferred to a CI runner provisioned with JDK + Android SDK + Xcode. Documented in `SPEC.md` `## Deferred items`. |
| 2026-08-14 | am-coder (Phase 3.3) | Default `mobile.target: "expo"` in `tier.config.json`. | Dossier recommends Expo (EAS Build + native signing handles the iOS/Android workflow). Users flip to `capacitor` when they want a web-hybrid shell without React Native. The default matches the choice in the agent-app-template family router. |
| 2026-08-14 | am-coder (Phase 3.3) | `app.json` uses `experiments.typedRoutes: true`. | Without it, `router.push('/items/123')` is `string -> void`; with it, the route is checked against the file structure at compile time. Matches the Expo Router 57 best practice. |
| 2026-08-14 | am-coder (Phase 3.3) | `capacitor.config.ts` uses `webDir: "dist"`. | The Vite build produces `dist/`; Capacitor wraps it as the native shell. The `webDir` key is the load-bearing field that ties the two targets together. |
| 2026-08-14 | am-coder (Phase 3.3) | No `src/db/DatabaseProvider.tsx` in this template. | The spine ships the shape (the file/lit layout) but does NOT ship Drizzle + Postgres schema. The schema lives in tier2-saas-bundle per the Phase 3.5 plan. The `src/lib/supabase.ts` client is the data-layer seam; the Drizzle provider is a follow-up. |
| 2026-08-14 | am-coder (Phase 3.3) | `tsc --noEmit` passes via top-level `import` for `@supabase/supabase-js` + `tsconfig.json` `resolveJsonModule: true` for `tier.config.json`. | The dynamic imports in `deepLinking.ts` use `typeof import(...)` for TS types; the runtime use `await import(...)`. No `any` casts needed. |
| 2026-08-14 | am-coder (Phase 3.3) | No `index.html` file in the skeleton. | Vite's `build.rollupOptions.input` points at `app/_layout.tsx` directly (mirrors tier1-standard's pattern of pointing at `src/main.tsx`). No `index.html` needed for the Vite build to produce `dist/`. Production Expo builds use Metro bundler; production Capacitor builds use the Vite `dist/` as the web bundle. |
| 2026-08-14 | am-coder (Phase 3.3) | `scripts/switch-target.sh` is a bash script that flips `mobile.config.ts` target + re-runs `npm install`. | The dispatch says "the postinstall or `npm install` script picks per toggle". A bash script is the cleanest cross-platform implementation; on Windows, `bash` is available via Git Bash or WSL. The postinstall hook in `package.json` runs this script on `npm install`. |
